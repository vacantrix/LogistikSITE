# Real-time шина ws-service (порт 3003)

Socket.io-сервис: после каждой значимой записи в БД сервер платформы дёргает
`notifyLive()` (`src/lib/notify.ts`) → шина рассылает событие `platform:update`
всем открытым вкладкам — списки и статусы обновляются без перезагрузки.

## События

`BID_PLACED`, `WINNER_AWARDED`, `DOCS_VERIFIED`, `PERMS_CHANGED` и др. —
вкладки по ним перечитывают свои данные через `api.*`.

## Подключение клиента

```ts
import { io } from 'socket.io-client'
const socket = io('/?XTransformPort=3003', { path: '/' })  // только так: шлюз Caddy
```

Прямые адреса `http://localhost:3003` в клиенте запрещены — единый внешний порт
проксируется Caddy по query-параметру `XTransformPort`.

## Авторизация

Шина пускает только с валидной сессией платформы: подписанная кука `aemz_session`
или `?token=` (Bearer) — проверка через `src/lib/auth.ts`.

## Запуск

```bash
cd mini-services/ws-service
bun install
bun run dev    # :3003 + внутренний /notify на 127.0.0.1:3004
```

Скрипт `dev` поднимает общий `.env` из корня проекта (`--env-file=../../.env`):
оттуда берётся `AUTH_SECRET` — без него шина пускает всех подряд (в логе будет
предупреждение), и работает `WS_NOTIFY_TOKEN`/`WS_ALLOWED_ORIGINS`, если заданы.
При старте в логе НЕ должно быть строки «AUTH_SECRET не задан» — если она есть,
env-файл не подхватился. Оба порта слушает один процесс: если `:3004` занят другим
экземпляром, события `/notify` будут уходить «в никуда» — держите ровно один процесс.

## Перезапуск и `bun --hot` (важно)

Автосупервизора у сервиса НЕТ: после падения или SIGTERM процесс не
перезапускается сам — клиенты видят «Нет связи с шиной реального времени»,
пока шину не поднимут вручную. Штатный способ (двойной fork, переживает
закрытие сессии):

```bash
# из корня проекта: daemonize держит cwd, а bun run dev нужен cwd мини-сервиса
cd /home/z/my-project/mini-services/ws-service
python3 /home/z/my-project/scripts/daemonize.py \
  /home/z/my-project/.zscripts/mini-service-ws-service.log bun run dev
```

`--hot` перечитывает код при правке файлов, но НЕ перезапускает сервер: новый
экземпляр падает с «Failed to start server. Is port 3003 in use?», а старый
продолжает работать на прежнем коде. Поэтому после правок `index.ts` нужен
полный рестарт командой выше — иначе правка не применится (аудит №3).

Обрывы связи у клиентов — штатное поведение: socket.io сам переподключается
(1–3 с), браузер показывает оверлей первые 8 секунд, затем неблокирующий
баннер — HTTP-автообновление (15–30 с) продолжает работать (Task 52 + аудит №3).
