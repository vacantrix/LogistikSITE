# Локальный OCR (PaddleOCR)

Распознаёт документы водителя на нашем сервере: фото паспортов и ВУ никуда не отправляются.
Правила проверки (сверка с заявкой, пороги, статусы) остаются на платформе (`src/lib/verify.ts`),
сервис только читает фото и находит независимые подтверждения на самом документе.

| Документ | Поля | Подтверждения от сервиса |
|---|---|---|
| Паспорт, страница с фото | ФИО, дата и место рождения, серия и номер (с полей страницы), дата выдачи, код подразделения | обе копии номера на полях совпали |
| Паспорт, регистрация | дата, код подразделения, адрес | — |
| Водительское удостоверение | ФИО, дата рождения, номер, категории, даты выдачи и окончания | латинская строка; повторное чтение категорий; срок = выдача + 10 лет |
| СТС, лицевая сторона | госномер (в т. ч. прицепа «АВ1234 23»), VIN, марка, номер СТС | — |
| СТС, оборот (`side: "back"`) | собственник, лизингодатель, срок временного учёта, номер СТС | — |
| Доверенность (М-2 и свободная форма) | номер, даты выдачи и окончания, кто выдал, представитель, его паспорт | номер, даты, представитель и организация совпали с корешком |

Заявку на перевозку сервис не читает (свободная форма) — на `type: REQUEST_DOC` он отвечает 422,
платформа отправляет такой документ на ручную сверку.

Форматы: JPG, PNG, WebP и PDF (распознаётся первая страница, 200 dpi). Мелкие сканы (меньше 1300 px)
увеличиваются вдвое — так подписи и номера читаются заметно лучше.

## Скорость

Все операции платформы читает одна сильная модель: детекция PP-OCRv5_server_det + чтение
eslav_PP-OCRv5_mobile_rec (5–25 с на фото документа, ~40 с на лист А4 в режиме экономии памяти).
Детекция ищет строки на кадре с лимитом по ПЛОЩАДИ входа (`OCR_DET_AREA`, 0,18 Мпикс по умолчанию)
— на фото паспорта 1500×2000 это ~38 с вместо 70 при тех же полях (сами строки читаются с исходного кадра).
Короткие поля, которые легко прочитать неверно (код подразделения, номер на полях паспорта),
перечитываются отдельной вырезкой.

Недочитанное добирают повторные проходы той же моделью (не вторая модель):
- документ вырезан с листа, но поля не дочитаны — проход по целому кадру;
- штамп прописки мелким шрифтом — проход по вырезке штампа в нативном разрешении (`stamp_pass`):
  строки в 3–4 раза крупнее, адрес читается целиком (боевой тест: из адреса оставался обрывок «КВ98»);
- кадр ×1,5 — если и после этого поля не дочитаны;
- документ не узнан — проход по развёрнутому на 180° кадру;
- в режиме экономии памяти ребёнок отработал, но документ не узнан или поля не дочитаны —
  второй процесс на ступень ниже лестницы (на другом лимите детекции строки находятся другие).

## Память

Пиковая память детекции ≈ 4–5 ГБ на МПиксель входа, а пул paddle растёт кумулятивно от прохода
к проходу, поэтому лимит по площади применяются ко ВСЕМ проходам (целая страница, вырезка, штамп,
полоса на полях). При свободной памяти меньше 6 ГБ (`OCR_LOW_MEMORY=1` или автоматически) документ
обслуживает короткоживущий процесс: модель грузится с нуля (~5–20 с), распознаёт один документ
и возвращает память системе; если процесс убит OOM — лестница спускается на ступень ниже
(меньше и кадр, и площадь).

## Точность

- **Словарь** (`lexicon.py`): регионы, города, слова штампов «Кем выдан» и адресов, имена и отчества
  (падежи и отчества порождаются правилами). Слово не из словаря меняется на близкое словарное
  («ВАРНАУЛ» → «БАРНАУЛ», «ФОРОДАВАРНАУЛА» → «ГОРОДА БАРНАУЛА», «ИБАН» → «ИВАН»), только если нейросеть
  сама допускала такое чтение: правдоподобие строки по выходу CTC хуже не больше чем на `OCR_LEX_TAU`
  (по умолчанию 4,5). Ошибки чтения на тестовых фото — 0…3,8, верные редкие слова (фамилии) — от 5,7:
  уверенно прочитанное слово не «исправляется». Правятся место рождения, «Кем выдан», адрес, имя и отчество.
- **Наклон**: фото с телефона в руке наклонено — координаты строк выпрямляются по среднему наклону,
  иначе соседние строки штампа меняются местами.
- **Фото боком и вверх ногами**: сторону поворота голосуют сами строки (классификатор ориентации),
  кадр поворачивается и читается ещё раз.
- **Подписи бланка** узнаются и прочитанные с ошибками («Meero» — «Место», «рожления»), конец адреса —
  по строке подразделения с ошибками («ОТАЕН ПО ВОПРОСАН ЕИГРАЦИИ»). «Г.» перед названием, прочитанное
  отдельным обрывком («F», «Γ.»), присоединяется к месту рождения.

Модели распознают по одному документу (общая блокировка); очередь держит платформа
(`src/lib/ocr-service.ts`), таймаут одного запроса — 180 с.

## Запуск

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt   # Windows: .venv\Scripts\pip
.venv/bin/python server.py                  # слушает 127.0.0.1:3031
```

Первый запуск скачивает модели PaddleOCR (~200 МБ) и загружает их 5–20 секунд. Держите окружение и модели
рядом с сервисом (`.venv`, `.models` — обе в .gitignore), а не во временной папке: автоочистка Windows
вычищает `%TEMP%`, и сервис перестаёт запускаться. Папка моделей — `PADDLE_PDX_CACHE_HOME=.models`;
скрипт `bun run dev` задаёт её сам. Скачанные модели (~105 МБ, пять папок в `.models/official_models`)
остаются на сервере: дальше сервис работает без интернета, на серверах без доступа к внешним хранилищам
модели достаточно один раз перенести вместе с `.models`.

## Подключение к платформе

- через OCR-шлюз `mini-services/ocr-service` (порт 3020): он по умолчанию обращается к `http://127.0.0.1:3031/ocr`;
- или напрямую: `OCR_SERVICE_URL=http://127.0.0.1:3031` в окружении платформы.

Переменные: `PADDLE_OCR_PORT` (порт, по умолчанию 3031), `OCR_SERVICE_TOKEN` (если задан — обязателен
заголовок `X-OCR-Token`; тот же токен задаётся платформе), `OCR_DET_MODEL` / `OCR_REC_MODEL` (модели;
по умолчанию PP-OCRv5_server_det + eslav_PP-OCRv5_mobile_rec — сильнейшая кириллическая связка
PaddleOCR: у server_rec и PP-OCRv6_rec словари без кириллицы), `OCR_UPSCALE_BELOW` (порог увеличения
мелких сканов), `OCR_DET_MAX_SIDE` (верхний лимит стороны кадра детекции, по умолчанию 1600),
`OCR_DET_AREA` (лимит площади входа детекции, Мпикс, по умолчанию 0,18 — см. «Память»),
`OCR_STAMP_TARGET` (размер вырезки штампа прописки, по умолчанию 1500),
`OCR_LOW_MEMORY` (1 — режим экономии памяти: процесс на документ, одна модель в памяти; без
переменной включается сам при свободной памяти меньше 6 ГБ), `OCR_PREP_TARGET` / `OCR_PREP_MAX_SCALE`
(маленький документ на листе вырезается и увеличивается до 1500 px, не больше чем втрое),
`OCR_LEX_TAU` (порог словарной правки, см. «Точность»).

Лестница памяти `_run_isolated` (свободная память): ≥2600 МБ — кадр `OCR_DET_MAX_SIDE` при 0,18 Мпикс,
затем 736 px/0,15 и 560 px/0,12; ≥1500 МБ — 560 px/0,18, 448 px/0,12, 384 px/0,09; ниже — 448/384/320 px
с площадью 0,12/0,09/0,07. Каждая ступень реально снижает память; ребёнка, убитого OOM, родитель
повторяет со следующей ступенью.

Облачной модели нет: если сервис не ответил, документ остаётся «на проверке» и проверку повторяют —
в ручную сверку он из-за недоступности сервиса не уходит.
