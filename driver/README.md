# АЗМЗ Логистика · drivemobile

Стенд автоматизации перевозок Абинского металлургического завода: диспетчерская
платформа **«Контур 1С»**, сервер **приложения водителя** (веб/PWA + API для
Android-каркаса) и **маршрутизатор** — единая точка входа. Всё разворачивается
на одной машине и работает с SQLite, без внешних сервисов.

```
                        ┌───────────────────────────────────────┐
                        │  Роутер :3000 — единая точка входа     │
                        │  /kontur/* → Контур 1С (:3001)         │
                        │  /*         → водительское приложение  │
                        └───────────┬───────────────┬───────────┘
                                    │               │
              ┌─────────────────────▼──┐   ┌────────▼────────────────┐
              │  «Контур 1С» :3001     │   │  Сервер водителя :3002  │
              │  рабочее место          │   │  Next.js + PWA + API    │
              │  диспетчера/логиста     │   │  (браузер и APK)        │
              │  SQLite custom.db       │   │  SQLite custom.db       │
              └────────────┬────────────┘   └─────────▲──────▲───────┘
                           │                                          │
        репликатор (тик 2 с): SyncJournal → POST /ingest              │
        водяная отметка db/bridge-state.json                          │
                           │                                          │
                           └────────────►─────────────────────────────┘
                                    (назначения, чат, заметки)

   Телефон водителя ──► :3002  REST API драйвера:
     · POST /sync/push    — исходящие операции (outbox, идемпотентно)
     · GET  /sync/pull    — личный журнал по курсору (канал 1)
     · GET  /sync/marks   — снимок пометок по bbox (канал 2)
     · GET  /traffic      — снимок пробок (канал 3)
     · POST /position     — GPS-телеметрия каждые 5 с (для диспетчера)
     · GET  /api/1c/orders — назначенные заявки (поллинг 5 с)

   «Контур 1С» ──► :3002  GET /api/driver/v1/position  (для «Мониторинг (GPS)»)
```

## Состав репозитория

| Путь | Что это | Порт |
|---|---|---|
| `src/`, `public/`, `db/` | Приложение водителя «АЗМЗ Логистика»: Next.js 15 + React 19 + Tailwind, PWA (service worker `public/sw.js`), API драйверского APK | 3002 |
| `kontur-1c/` | Платформа «Контур 1С»: рабочее место логиста и диспетчера (заявки, маршрутные листы, рейсы, мониторинг GPS, чат, справочники, журнал) | 3001 |
| `scripts/router.js` | Роутер-прокси: один порт наружу, раздаёт `/kontur` и корень на два приложения (HTTP + WebSocket) | 3000 |
| `scripts/start-stack.sh` | Подъём всего стенда одной командой | — |
| `download/azmz-karkas/` | Каркас нативного Android-приложения (Kotlin/Compose/Room/WorkManager, 9 Gradle-модулей) и скелет Spring Boot-бэкенда с миграциями Flyway | — |
| `docs/` (в karkas) | ER-диаграмма и схема потоков синхронизации каркаса | — |

## Компоненты системы

### 1. «Контур 1С» — диспетчерская (порт 3001, basePath `/kontur`)

Рабочие разделы: Главная · Заявки · Маршрутные листы · Рейсы ·
**Мониторинг (GPS)** · Обсуждение · Справочники · Журнал регистрации · Демо-панель.
Роль выбирается в интерфейсе (Логист / Диспетчер / Админ), экраны фильтруются по роли.

Ключевые сценарии:
- **Заявка → Проводка → Назначение**: диспетчер проводит заявку (кнопка
  «Провести», проверяются вес, ТС, водитель), назначает водителя и транспорт —
  создаётся рейс, строятся маршрутные точки и геометрия (OSRM-снаппинг).
- **Принудительное завершение рейса**: в карточке рейса кнопка
  «Завершить рейс (принудительно)» — для висящих рейсов, мешающих новому
  назначению (событие TRIP_DONE/MANUAL + системная заметка водителю).
- **Мониторинг (GPS)**: живые позиции машин (SVG-мини-карта с маршрутом,
  скорость, связь с активным рейсом; позиция старше 5 минут помечается
  «потерянной»). Блок позиции — также в карточке рейса.
- **Мост к водителю** (репликатор): каждая запись плана обмена `SyncJournal`
  пересылается на сервер водителя `/api/driver/v1/ingest` с токеном; пересылаются
  только записи водителей с заполненным `appId` (id привязки телефона).

### 2. Приложение водителя (порт 3002)

Веб-приложение/PWA: до старта рейса — полноэкранные «Главная / История /
Настройки» (взять заявку, фотофиксация ТС и документов); после «Начать маршрут» —
карта как постоянный фон (MapLibre + OSM-тайлы, локальный кэш), экраны — шторками.

Синхронизация — офлайн-first, цикл каждые 4 с:
- **Исходящие** — outbox с UUID-операциями, `POST /sync/push` (идемпотентно,
  сервер отсеивает дубли); индикатор связи: «На связи» / «Отправка: N» / «Офлайн. В очереди: N».
- **Входящие канал 1** — личный журнал по курсору `GET /sync/pull`: рейсы,
  точки, события, чат, системные заметки.
- **Канал 2** — пометки дорожной обстановки (аварии, ремонты…) — снимок по bbox
  коридора маршрута, TTL 6 ч / 12 ч / 30 дней, голоса водителей.
- **Канал 3** — пробки по сегментам коридора, ETA с поправкой.
- **Заявки из 1С** — поллинг раз в 5 с: назначение диспетчера появляется
  «по ходу», со спиннером загрузки на карточке ожидания; тик синхронизации
  также запускается при возврате на экран (visibilitychange/focus/pageshow —
  мобильный браузер не ждёт следующего цикла после фона).
- **GPS-телеметрия** — во время рейса `POST /position` каждые 5 с: диспетчер
  видит машину в разделе «Мониторинг (GPS)».

### 3. Роутер (порт 3000)

`scripts/router.js`: слушает `0.0.0.0:3000`, `/kontur/*` проксирует на
127.0.0.1:3001, остальное — на 127.0.0.1:3002; WebSocket-апгрейды (HMR дев-режима)
туннелируются напрямую. Позволяет отдавать оба приложения через один порт/домен.

### 4. Каркас Android-приложения (`download/azmz-karkas`)

Нативный каркас (Kotlin, Compose, Room, WorkManager, MapLibre, OSRM) —
архитектурный эталон прод-приложения: 9 модулей, ER и потоки синхронизации
описаны в его `README.md`. Сборка APK — GitHub Actions
(`.github/workflows/android-apk.yml`, артефакт `azmz-driver-apk`).

Отличия от веб-версии (важно для демо):
- синхронизация по расписанию WorkManager — минимальный интервал 15 минут
  (плюс внекачеденный цикл при старте приложения и возврате связи), поэтому
  «мгновенных» назначений, как в веб-версии, в APK нет;
- GPS-телеметрия для «Мониторинга (GPS)» в каркасе не реализована;
- адрес сервера и демо-водитель зашиты в
  `android/core/sync/.../AppGraph.kt` (`DEFAULT_BASE_URL`, `DEFAULT_DRIVER_ID`).
Для полнофункционального демо используйте веб-версию/PWA (порт 3002/3000).

## Каналы синхронизации и API

### Сервер водителя (:3002, используется и веб-версией, и APK)

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | `/api/driver/v1/sync/push` | Батч outbox-операций (TRIP_EVENT_CREATE, CHAT_SEND, NOTE_READ, MARK_PUBLISH, MARK_VOTE); ответ по каждой: APPLIED / DUPLICATE / REJECTED |
| GET | `/api/driver/v1/sync/pull?cursor=N` | Дельта личного журнала (TRIP, TRIP_POINT, TRIP_EVENT, CHAT_MESSAGE, SYSTEM_NOTE) |
| GET | `/api/driver/v1/sync/marks?bbox&since` | Снимок активных пометок по коридору маршрута |
| GET | `/api/driver/v1/traffic?bbox&since` | Снимок пробок по сегментам |
| POST | `/api/driver/v1/position` | GPS-фикс каждые 5 с во время рейса |
| GET | `/api/driver/v1/position?driverId&maxAgeMs` | Позиции для мониторинга (использует «Контур 1С») |
| POST | `/api/driver/v1/ingest` | Приём реплики от «Контура 1С» (токен `azmz-stand-bridge-2026`) |
| GET | `/api/1c/orders` | Заявки, назначенные водителю (поллинг 5 с) |
| GET | `/api/2gis/*`, `/api/maptiles/*`, `/api/mapstyle` | Картографические сервисы (2ГИС-ключ, тайлы, стиль) |

Идентификация — заголовок `X-Driver-Id` (у демо-водителя совпадает с `appId`
из 1С, см. ниже).

### «Контур 1С» (:3001)

| Метод | Endpoint | Назначение |
|---|---|---|
| GET/POST | `/kontur/api/1c/orders` | Заявки терминала 1С (просмотр/действия) |
| GET | `/kontur/api/office/dashboard` | Сводка дашборда |
| GET/POST | `/kontur/api/office/requests` (+`/[id]/assign`, `/[id]/cancel`) | Заявки: проведение, назначение, отмена |
| GET | `/kontur/api/office/trips`, POST `/kontur/api/office/trips/[id]/complete` | Рейсы; принудительное завершение |
| GET | `/kontur/api/office/tracking` | Живые GPS-позиции, связанные с водителями/рейсами |
| GET/POST | `/kontur/api/office/chat` | Обсуждения |
| GET | `/kontur/api/office/journal`, `/kontur/api/office/catalog/[entity]` | Журнал регистрации, справочники |
| POST | `/kontur/api/office/demo` | Демо-панель (генерация данных) |

## Демо-данные

Базы SQLite с демо-данными лежат в репозитории (`db/custom.db`,
`kontur-1c/db/custom.db`):

- **Водитель**: Иванов Сергей Петрович — единственный с привязкой телефона
  (`appId = 06c075d1-3088-45f2-a7ae-090e8c355447`); все назначения из 1С
  реплицируются на его устройство.
- Справочники: 12 водителей, транспорт (КАМАЗ, Scania, MAN…), локации
  Кубани (Абинск, Краснодар, Новороссийск, Тимашевск…).
- Демо-заявки со статусами всей цепочки: от новой до выполненной.

## Быстрый старт

Требования: Node.js 20+ (или bun 1.x), ~2 ГБ диска.

```bash
npm install                 # зависимости сервера водителя (корень)
cd kontur-1c && bun install && cd ..   # зависимости «Контура 1С»
bash scripts/start-stack.sh  # поднимет :3001, :3002 и роутер :3000
```

Проверка: `http://127.0.0.1:3000/` — водитель; `http://127.0.0.1:3000/kontur` — диспетчер.

Развёртывание на своей машине (ПК как сервер, телефон по Wi-Fi, сборка APK
под свой адрес) — пошагово в **[DEPLOY-LOCAL.md](./DEPLOY-LOCAL.md)**.

## Переменные окружения

| Переменная | По умолчанию | Где | Смысл |
|---|---|---|---|
| `KONTUR_1C_URL` | `http://127.0.0.1:3001/kontur` | водитель :3002 | Адрес «Контура 1С» для поллинга заявок (basePath `/kontur` обязателен) |
| `DATABASE_URL` | `file:.../db/custom.db` | оба | Путь к SQLite (у Контура — свой файл!) |
| `KONTUR_DRIVER_URL` | `http://127.0.0.1:3002` | контур :3001 | Адрес сервера водителя (мониторинг GPS) |
| `DRIVER_BRIDGE_URL` | `http://127.0.0.1:3002/api/driver/v1/ingest` | контур :3001 | Приёмник реплики |
| `DRIVER_BRIDGE_TOKEN` | `azmz-stand-bridge-2026` | контур :3001 | Токен моста |
| `DRIVER_BRIDGE_STATE` | `kontur-1c/db/bridge-state.json` | контур :3001 | Водяная отметка репликатора |
| `DRIVER_BRIDGE_DISABLED` | — | контур :3001 | `1` — выключить мост |

## Технологии

Next.js 15 (App Router, Turbopack) · React 19 · TypeScript · Tailwind CSS 4 ·
Prisma + SQLite · Zustand (стор водителя, персистент в localStorage) ·
MapLibre GL / OSM / 2ГИС · OSRM (маршрутизация по дорогам) · PWA (service
worker, офлайн-кэш) · Kotlin/Compose/Room/WorkManager (каркас APK) ·
Spring Boot + Flyway (скелет прод-бэкенда в karkas).
