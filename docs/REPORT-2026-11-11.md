# Отчёт: ускорение OCR-контура — итоги 10–11.11.2026

Ветка fix/ui-review, изменения не закоммичены. На момент отчёта ПК был выключен по просьбе
пользователя после реализации и тестов; сейчас стопка поднята. Автозапуск — задача
«LogistikSITE-Demo» при входе в систему (вручную: `publish/start-production.ps1 -NoPause`).

## Диагноз (10.11)

Боевой паспорт шёл **184.8 с** (таймаут клиента был 180 с) — платформа обрывала запрос
(WinError 10053 в err.log), результат терялся, в карточке оставалась только регистрация.
Причина: до 5 проходов на документ, которые раз за разом запускали закономерно пустые
«Дата выдачи»/«Код подразделения».

## Что сделано

### Раунд 1 (10.11)
- **Бюджет времени** на документ `OCR_TIME_BUDGET=90 с` + запас `PASS_RESERVE=20 с`:
  каждый дополнительный проход — только пока бюджет позволяет; телеметрия
  (`elapsedMs`, `passes`, `stopReason`) в ответе и логе.
- **Ключевые поля** (`KEY_FIELDS`): повторы только ради них; поле, пустое на двух масштабах,
  фиксируется как «не читается на этом фото»; ×1.5 поднят перед добором лёгкой моделью.
- **Клиент**: таймаут = бюджет + 60 с (мин. 150 с); LRU-кэш 20 записей / TTL 10 мин
  по sha256(фото)+тип, флаг `cached`; server.py логирует обрыв клиента одной строкой.
- **UI**: таймер оверлея («N с · обычно до минуты»), тост «Фото нечитаемое — переснимите»
  при quality<60 и ≥2 пустых ключевых полях (водитель/ТС/прицеп), панель «Что прочитала
  нейросеть» показывает и пустые поля — явным «не прочитано».

### Раунд 2 (11.11)
- **Пропуск OCR по качеству**: платформа передаёт `minQuality` (настройка, по умолчанию 60)
  в движок; размытее порога — нейросеть не работает вовсе (`stopReason="quality"`,
  0 проходов). Размытое фото 3000 px: **71.8 с → 0.3 с**.
- **Ранний выход** в `read_margin_number` (уверенный номер с первого поворота полосы).
- Попытка «слепых полос полей» вместо прохода ×1.5 — **реализована, замерена и отклонена**:
  детекция на голой полосе вне распределения, недетерминированна (одинаковый масштаб —
  разные результаты), ожидаемая выгода ~4 с против риска 62 с при промахе.
- **Дисковый кэш распознавания** `.ocr-cache/` (файлы JSON: версия, потолок 200
  записей, TTL 30 дней; само фото не хранится): быстрый локальный слой перед БД.

### Раунд 3 (11.11) — кэш в БД
- **Таблица `OcrCache`** (SQLite): ключ — версия логики + sha256(dataUri) + вид документа +
  `minQuality`; TTL 30 дней, потолок 5000 записей, очистка просроченных раз в 10 минут.
  Хранится только результат OCR, само фото не пишется. Схема применена `prisma db push`.
- Порядок слоёв: память (20 записей / 10 мин) → диск (`.ocr-cache/`) → БД. Любая ошибка БД
  (нет таблицы, занята, нет прав) отключает только этот слой — распознавание работает как обычно.
- В долговременные слои пишутся только полные результаты: `stopReason=budget/quality` не кэшируются.
- Проверка через `/api/documents/check` + `/api/ocr-jobs`: паспорт 41.6 с → рестарт платформы +
  удаление `.ocr-cache/` → 1.0 с по API (сам OCR 0.1 с, `cached=true`, лог «кэш в БД»);
  регистрация 14.2 с → 1.0 с; размытое фото — 1.0 с, `REUPLOAD`, в БД не попало.

### Раунд 4 (11.11) — проверки при подъёме сайта

- **`publish/build-manifest.ps1`** — манифест целостности: SHA-256 дерева `src`, `public`,
  корневых конфигов сборки (`package.json`, `bun.lock`, `next.config.ts`, `tsconfig.json`,
  `postcss.config.mjs`, `tailwind.config.ts`, `components.json`, `prisma/schema.prisma`,
  `.env.local`), а также артефактов `.next/standalone` (`server.js`, деревья `server`,
  `static`, `public`). Манифест пишется в `publish/build-manifest.json`.
- **`publish/build-public.ps1`** — после успешной сборки автоматически пишет манифест;
  без него проверка при запуске считает сборку неполной.
- **`publish/verify-stack.ps1`** — три независимые проверки:
  `architecture` (порты 3000/3031/8080/8090 только на loopback, Caddy на 443, БД,
  маршруты Caddyfile, HTTP/health), `access` (вход admin, `/api/admin/access`,
  `/api/permissions`, 9 должностей, 8 пользователей, ровно одна основная должность
  в каждом контуре, запрет 403 не-админу, 401 без токена), `build` (BUILD_ID и хеши
  исходников/артефактов совпадают с манифестом).
- **`publish/start-all.ps1`** — проверяет сборку до запуска сервисов (старая или битая
  сборка останавливает подъём с подсказкой пересобрать), после Caddy проверяет
  архитектуру и права; любой провал — `ERROR` и ненулевой код возврата.
- **`publish/status.ps1`** — выводит все три проверки и учитывает их в `RESULT`.

Проверено на текущей сборке `1kZ3t3lXjNciOIZEkZ-K7`: 206 файлов исходников, 574 файла
артефактов; `start-all.ps1` и `status.ps1` → `RESULT: OK`. Негативные тесты: добавленный
