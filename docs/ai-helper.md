# ИИ-помощник, «Память контактов» и «Избранное»

Обе функции входят в состав платформы «АЭМЗ Поток» и не требуют отдельных лицензий.

## 1. Память контактов

Раздел в меню «Привлечённый транспорт» → «Память контактов»: с кем работали и какие
сделки заключались. Ведётся вручную (логист сам заносит людей и сделки), это рабочая
тетрадь — не справочник допущенных перевозчиков.

- Типы контактов: перевозчик, грузовладелец, водитель, другое; рейтинг 0–5.
- Сделки: груз («нашли груз») или машина («нашли перевозчика»), маршрут, груз, сумма,
  статус — переговоры / заключена / отказ / не вышло.
- Незаключённые тоже сохраняются: чтобы не звонить повторно в пустоту.
- Кнопка «+ Контакт», «+ Сделка» — диалоги; карточка раскрывается по клику.

Модели — `MemoryContact` и `MemoryDeal` в `prisma/schema.prisma`; API — `/api/contacts`
и `/api/deals`. Раздел закрыт правом `section:contacts`.

## 2. ИИ-помощник (нейросеть-консультант)

Роль — помощник-консультант; основная работа — подбор грузов и перевозчиков на ATI.SU.
Движок — **GigaChat (Сбер)**, только серверная часть: `src/lib/ai` + API `/api/ai/*`.
Ключи `GIGACHAT_CLIENT_ID` и `GIGACHAT_CLIENT_SECRET` читаются из `.env.local`
(необязательно `GIGACHAT_MODEL`, `GIGACHAT_SCOPE`). На клиент ключи не попадают.
Раздел виден логисту и администратору: на телефоне — нижняя вкладка «ИИ», на
компьютере — отдельная полоса по центру между «Привлечённым транспортом» и
«Собственным транспортом», а также боковое меню «ИИ-помощник».
Перевозчику раздел недоступен. Не путать с разделом «Нейросеть» в меню
«Управление»: там настройки распознавания документов (OCR), а не чат GigaChat.

### Что умеет

- **Чат** — консультации: разборы грузов/машин, ориентиры ставок, риски, черновики
  сообщений. Уровень GigaChat выбирается рядом с кнопкой отправки; ход работы
  выводится простым текстом в ленте.
- **Окно «Что найти»** — кнопка «Найти с ИИ» в разделе ATI.SU: выбираете «Грузы /
  Машины / И то и другое», описываете задачу — нейросеть разбирает запрос и
  показывает витрину грузов и (при подключённом ATI.SU) машины фирмы.
- **Свой список** — каждый разбор сохраняется в список нейросети (`AiListItem`,
  раздел «ИИ-помощник»). Последний разбор показывается сразу после запроса и в
  боковом меню справа.
- **Избранное** — на карточках списка есть кнопка «В избранное» (`AiFavorite`).
  Раздел «Избранное» в меню показывает отобранные варианты: маршрут, ставка,
  компания, контакт, запрос и примечание. Отсюда можно позвонить, скопировать
  карточку или убрать вариант; переговоры по варианту хранятся в
  `AiFavoriteMessage`. API — `GET/POST/DELETE /api/ai/favorites`.
- **Логи** — журнал нейросети (`AiLog`): что она делала и когда.

### Права — жёстко ограничены

| Что | Право |
|---|---|
| Свой список разборов (`AiListItem`), избранное (`AiFavorite`, `AiFavoriteMessage`), журнал (`AiLog`) | запись — единственное, что она пишет |
| Память контактов | частичное чтение: имена/компании/роли/статусы, телефоны и почта скрыты |
| Витрина ATI.SU (демо-данные) | чтение для разбора запроса |
| Контакты, сделки, заявки, рейсы, ЭДО, 1С, Диадок | запрещено — только подсказки |
| Персональные данные (паспорта, телефоны, пароли) | не передаются модели вовсе |

Права зашиты на сервере: контекст для модели собирает сервер из разрешённых источников;
сама модель никаких операций с базой платформы выполнять не может. Матрица режимов
редактируется администратором в разделе «ИИ-помощник» → «Права».

### Честно про данные ATI.SU

Витрина грузов — демо-заглушка (генерируется локально, реальные запросы на api.ati.su
не отправляются). После покупки подписки и токена ATI.SU выдача переключится на реальные
данные без изменения интерфейса (см. комментарии в `src/lib/kontur/atisu/`).
Поиск машин требует подключённого токена — до этого нейросеть даёт консультацию
по описанию задачи и подсказывает, где искать.

## 3. Установка и база

На своём стенде (Windows) из каталога проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\publish\install-ai.ps1            # зависимости + Prisma-клиенты
powershell -ExecutionPolicy Bypass -File .\publish\install-ai.ps1 -PushDb    # + безопасно добавить таблицы ИИ
```

Скрипт ставит зависимости, генерирует Prisma-клиенты обеих схем (лечит ошибку сборки
`Module not found: '@/generated/kontur-client'` после чистого клона) и по `-PushDb`
вызывает `publish/ensure-ai-tables.ps1`. Тот создаёт временную пустую схему, берёт из
неё DDL только недостающих таблиц ИИ и добавляет их в рабочую базу — **без удаления**
существующих таблиц и данных.

При каждом запуске `publish/start-all.ps1` проверяет таблицы ИИ через
`publish/check-ai-tables.py`; если чего-то не хватает, безопасно вызывает
`ensure-ai-tables.ps1`. Затем проверяется, что маршрут `/api/ai/favorites`
смонтирован (401 без сессии — норма), и печатается состояние GigaChat:
`configured` или `not configured`. Данные при этой проверке не меняются.

### Важно про базы

Платформа и диспетчерская используют **одну** SQLite-базу `db/combat.db`; таблицы
диспетчерской лежат с префиксом `Dispatch` (`DispatchUser`, `DispatchOrder`, …).
`KONTUR_DATABASE_URL` указывает на ту же базу (его выставляет `publish/config.ps1`
при запуске). Обычный `prisma db push` на рабочей базе **запрещён**: он синхронизирует
базу под одну схему и удаляет таблицы другой. Для существующей базы используйте только
`ensure-ai-tables.ps1`.

На чистой базе порядок такой:

1. `npm run db:push` — схема платформы (включая таблицы ИИ и памяти контактов);
2. таблицы диспетчерской — `python publish/migrate-kontur-db.py --src <kontur.db> --dst db/combat.db --replace`
   (см. [architecture/data-model.md](architecture/data-model.md));
3. `npm run db:generate` — клиенты Prisma.

### Ключи GigaChat

Добавьте в `.env.local`:

```
GIGACHAT_CLIENT_ID=...
GIGACHAT_CLIENT_SECRET=...
# необязательно:
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2-Max
```

Без ключей чат честно отвечает «GigaChat не настроен», а остальные разделы платформы
(контакты, заявки, рейсы, ЭДО) работают как обычно. После изменения ключей
перезапустите стенд (`publish/start-all.ps1`): `.env.local` — runtime-конфигурация,
она не входит в отпечаток сборки, пересборка не нужна.

## 4. API

| Маршрут | Назначение |
|---|---|
| `POST /api/ai/chat` | чат с GigaChat (история, уровни модели, файлы) |
| `POST /api/ai/search` | разбор поискового запроса «Что найти» |
| `GET/DELETE /api/ai/list` | список разборов нейросети |
| `GET /api/ai/logs` | журнал действий нейросети |
| `GET/POST/DELETE /api/ai/favorites` | избранные варианты (сохранение, список, удаление) |
| `GET/PATCH /api/ai/rights` | матрица прав (администратор) |
| `GET/POST /api/contacts`, `GET/PATCH/DELETE /api/contacts/[id]` | память контактов |
| `GET/POST /api/contacts/[id]/deals`, `GET/PATCH/DELETE /api/deals/[id]` | сделки |

Все маршруты требуют сессию логиста или администратора (`requireUser('logist', 'admin')`).
