# ИИ-помощник и «Память контактов»

Обе функции входят в состав платформы «АЭМЗ Поток» и не требуют отдельных лицензий.

## 1. Память контактов

Раздел в меню «Привлечённый транспорт» → «Память контактов»: с кем работали и какие
сделки заключались. Ведётся вручную (логист сам заносит людей и сделки), это рабочая
тетрадь — не справочник допущенных перевозчиков.

- Типы контактов: перевозчик, грузовладелец, водитель, другое; рейтинг 0–5.
- Сделки: груз («нашли груз») или машина («нашли перевозчика»), маршрут, груз, сумма,
  статус — переговоры / заключена / отказ / не вышло.
- Незаключённые тоже сохраняются: чтобы не звонить повторно в пустоту.
- Кнопка «+ Контакт», «+ Сделка» — диалоги; карточка раскрывается по клику.

## 2. ИИ-помощник (нейросеть-консультант)

Роль — помощник-консультант; основная работа — подбор грузов и перевозчиков на ATI.SU.
Технически: серверный модуль `src/lib/ai` + API `/api/ai/*` (chat, search, list, logs),
модель подключается через `z-ai-web-dev-sdk` (только backend — на клиент SDK не попадает).

### Что умеет

- **Чат** — консультации: разборы грузов/машин, ориентиры ставок, риски, черновики сообщений.
- **Окно «Что найти»** — кнопка «Найти с ИИ» в разделе ATI.SU: выбираете «Грузы / Машины /
  И то и другое», описываете задачу — нейросеть разбирает запрос и показывает витрину
  грузов и (при подключённом ATI.SU) машины фирмы. Ответ выводится сразу.
- **Свой список** — каждый разбор сохраняется в список нейросети (раздел «ИИ-помощник» →
  «Список ИИ», боковое меню справа тоже показывает последний разбор). Человек смотрит
  в любой момент; последний — сверху и выводится сразу после выполнения запроса.
- **Логи** — журнал нейросети: что она делала и когда (обновление каждые 10 секунд).

### Права — жёстко ограничены

| Что | Право |
|---|---|
| Свой список разборов (AiListItem) и журнал (AiLog) | запись — единственное, что она пишет |
| Память контактов | частичное чтение: имена/компании/роли/статусы, телефоны и почта скрыты |
| Витрина ATI.SU (демо-данные) | чтение для разбора запроса |
| Контакты, сделки, заявки, рейсы, ЭДО, 1С, Диадок | запрещено — только подсказки |
| Персональные данные (паспорта, телефоны, пароли) | не передаются модели вовсе |

Права зашиты на сервере: контекст для модели собирает сервер из разрешённых источников;
сама модель никаких операций с базой платформы выполнять не может.

### Честно про данные ATI.SU

Витрина грузов — демо-заглушка (генерируется локально, реальные запросы на api.ati.su
не отправляются). После покупки подписки и токена ATI.SU выдача переключится на реальные
данные без изменения интерфейса (см. комментарии в `src/lib/kontur/atisu/`).
Поиск машин требует подключённого токена — до этого нейросеть даёт консультацию
по описанию задачи и подсказывает, где искать.

## 3. Установка через PowerShell

На своём стенде (Windows) из каталога проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\publish\install-ai.ps1            # зависимости + Prisma-клиенты
powershell -ExecutionPolicy Bypass -File .\publish\install-ai.ps1 -PushDb    # + создать таблицы (первый запуск)
```

Скрипт ставит зависимости (ИИ-модуль уже в составе — отдельная установка не нужна),
генерирует Prisma-клиенты обеих схем (лечит ошибку сборки
`Module not found: '@/generated/kontur-client'` после чистого клона) и по `-PushDb`
создаёт таблицы: MemoryContact, MemoryDeal, AiListItem, AiLog.

Важно про базы: у платформы и диспетчерской **разные** SQLite-базы.
`-PushDb` применяет основную схему к DATABASE_URL, а контурную — в отдельную
базу `db/kontur.db` и прописывает `KONTUR_DATABASE_URL` в `.env.local`
(её читает сервер в `src/lib/kontur/db.ts`). Пушить контурную схему в общую базу
нельзя: prisma db push синхронизирует базу под схему и удалит чужие таблицы.

Подключение самой нейросети в среде разработки Z.AI работает из коробки (SDK читает
ключи из окружения). На собственном сервере ключи подписки Z.AI добавьте в `.env.local`
по документации SDK — код менять не нужно.
