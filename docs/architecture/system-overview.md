# Архитектура системы

## 1. Назначение

«АЭМЗ Поток» закрывает два контура перевозок АЭМЗ:

- **привлечённый транспорт** — площадка заявок, торги, кабинет перевозчика,
  документы, нейропроверка, сверка логистом, реестр рейсов, отчёты, ЭДО;
- **собственный парк** — заявки 1С/ATI.SU, планирование, занятость, рейсы,
  назначение водителя и ТС, GPS-мониторинг, маршруты.

Оба контура работают в одной платформе, одной базе и одном интерфейсе.
Модуль водителя — отдельное Next.js-приложение, смонтированное в `/driver`
и доступное только через gateway платформы.

## 2. Контекст

```
логист / админ ─┐
перевозчик ─────┼── HTTPS ── Caddy ── gateway ── платформа :3000
водитель ───────┘                              ├── /kontur
                                               ├── /api/*
                                               └── SQLite combat.db
1С:ERP ─────────── REST /api/integration/1c/* ─┘
ATI.SU ─────────── API /kontur/api/atisu/* ────┘
Диадок ─────────── ЭТрН /api/edo/* ────────────┘
```

```
                  └───┬─────────────┬───┘
                      │             │
          /driver/*,  │             │  остальное
          /api/driver,│             │
          /api/1c/*   │             │
                      ▼             ▼
             ┌────────────────┐  ┌──────────────────────────┐
             │ driver :3102   │  │ platform :3000           │
             │ basePath       │  │ Next.js standalone       │
             │ /driver        │  │ + /kontur + REST         │
             └───────┬────────┘  └───────┬──────────────────┘
                     │                   │

             driver/db/custom.db         ├── ws :3003

```

Все внутренние сервисы слушают `127.0.0.1`. Наружу открыт только Caddy.
Исключение — WS-шина на стенде: gateway/Caddy проксирует её по
`?XTransformPort=3003`, остальные порты наружу не отдаются.

| Компонент | Технология | Ответственность |
|---|---|---|

| PaddleOCR | Python, PaddleOCR/PaddleX | чтение документов, поля и уверенности |

| Диадок-мок | Node | имитация ЭТрН на стенде |
| Caddy | Caddy 2 | TLS, домены, статика, reverse proxy |

## 5. Потоки данных

### 5.1. Заявка и торги

```
логист → POST /api/requests → Request (PUBLISHED)
перевозчик → POST /api/requests/[id]/action (bid/take)
логист → award → Request (AWARDED)
перевозчик → assign (водитель/ТС) → documents → verify
логист → confirm → реестр/1С → CLOSED
```

Все действия пишут `Event`, часть — `Notification` и `PlatformLog`. После
записи в БД платформа отправляет `platform:update` в WS-шину.

### 5.2. Документы и OCR

```
браузер → сжатие (2400 px, JPEG 92%) → POST /api/requests/[id]/documents
       → Document(dataUri) → POST .../verify
       → src/lib/ocr-service.ts → OCR-шлюз :3020
       → PaddleOCR :3031 → поля + confidence
       → src/lib/verify.ts → PASSED / REUPLOAD / REJECTED / MANUAL
```

Очередь общая: одновременно обрабатывается не больше `nnParallel` фото.
Лишние ждут. Повторный скан ищется в кэше по хэшу. Если OCR недоступен,
документ остаётся `PENDING`/`MANUAL`, а не подменяется фиктивным результатом.

### 5.3. Рейс и маршрут

```
1С/ATI.SU → DispatchOrder → «Провести» → DispatchTrip + DispatchLeg
логист → назначает водителя/ТС → TRIP в журнале водителя
логист → вставляет ссылку Яндекс.Карт → /kontur/api/trip/[id]/route-link
       → yandex-route.ts: rtext → geometry
       → driver-bridge.ts: ingest в модуль водителя
водитель → sync/pull/long-poll → PWA/APK строит линию
```

Приоритет геометрии:

1. точная линия Яндекс.Карт (`routeSource=yandex`);
2. OSRM через сохранённые точки по порядку (`routeSource=osrm`) — только если
   линии Яндекса нет;
3. демо/локальная линия — только для офлайн-сида.

### 5.4. Синхронизация водителя

```
PWA/APK → sync/push (outbox, UUID) → сервер применяет идемпотентно
PWA/APK ← sync/pull?cursor=N ← журнал изменений
PWA/APK ← sync/wait (long-poll 25 с) ← просыпается при записи
```

Исходящие при обрыве копятся в localStorage/Room и досылаются после сети.
Входящие не теряются: курсор двигается только после применения пачки.
Резервный polling 15 с страхует от старого прокси, который режет long-poll.

## 6. Отказоустойчивость и деградация

| Отказ | Поведение |
|---|---|
| OCR недоступен | документ остаётся на проверке/ручной сверке, ошибка в журнале; платформа работает |
| Яндекс не отдал страницу | OSRM строит линию через точки, водитель видит «линия по точкам» |
| long-poll недоступен | резервный polling каждые 15 с; outbox не теряется |
| Сеть пропала | PWA показывает офлайн-оболочку, APK — локальные данные; очередь сохраняется |
| WS-шина упала | интерфейс работает, обновление — по действию/поллингу |
| Модуль водителя упал | платформа и «Контур» работают; водитель видит ошибку связи |
| Gateway упал | внутренние сервисы живы, внешний вход недоступен |
| Диадок недоступен | ЭТрН остаётся в очереди/со статусом, реестр и рейсы работают |

## 7. Границы ответственности

- Платформа — единственный источник бизнес-правил и прав.
- Модуль водителя не содержит админки и не показывает чужие заявки.
- OCR только читает документ; вердикт выносит `src/lib/verify.ts`.
- 1С — внешняя система; обмен идемпотентен по `external_id`.
- APK — клиент; офлайн-очередь и курсор живут на устройстве.
