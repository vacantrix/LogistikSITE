# Интеграция с 1С

Двусторонний обмен: 1С создаёт черновики заявок и подтверждает ЭТрН, платформа
возвращает статусы, победителя, ставку, экипаж и реестр рейсов.

## 1. Авторизация и адрес

- Заголовок `X-API-Key: <ONEC_API_KEY>`; ключ не короче 24 символов.
- Без `ONEC_API_KEY` все маршруты `/api/integration/1c/*` отвечают `503`.
- Сравнение ключа — за постоянное время.
- CORS включается только для `ONEC_CORS_ORIGINS` (нужен симулятору и
  браузерным проверкам); 1С ходит с сервера, ей CORS не нужен.
- Базовый адрес production: `https://logistiksite.vacantrix.ru`.

## 2. Маршруты

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/integration/1c/ping` | проверка связи и ключа |
| `GET` | `/api/integration/1c/info` | версия, возможности, часовой пояс |
| `POST` | `/api/integration/1c/requests` | создать черновик заявки |
| `GET` | `/api/integration/1c/requests?onecRef=…` | статус одного документа |
| `GET` | `/api/integration/1c/requests?since=…` | реестр изменений |
| `POST` | `/api/integration/1c/etrn` | подтвердить ЭТрН |
| `GET` | `/api/integration/1c/dictionaries` | справочники для 1С |

## 3. Создание заявки

```json
{
  "oneC_number": "ЗП-0012 от 28.10.2026",
  "fromPoint": "Краснодарский край, г. Абинск, ул. Промышленная, д. 4",
  "toPoint": "г. Санкт-Петербург, Канонерский остров, д. 45",
  "cargo": "Перевозка готовой продукции - арматура",
  "tonnage": 20.5,
  "truckType": "Борт",
  "loadDate": "2026-10-30",
  "loadWindow": "09:00–18:00",
  "startRate": 4200,
  "mode": "AUCTION",
  "comment": "Срочная доставка"
}
```

| Поле | Обяз. | Правила |
|---|---|---|
| `oneC_number` | да | ключ документа до 100 символов; повтор не создаёт дубль |
| `fromPoint`, `toPoint` | да | адреса текстом до 300 символов |
| `cargo` | да | сравнение со справочником без регистра; новый груз добавляется |
| `loadDate` | да | `ГГГГ-ММ-ДД`, ISO с временем или `ДД.ММ.ГГГГ`; прошедшая отклоняется |
| `tonnage` | нет | `0 < x ≤ 200`, по умолчанию 20 |
| `truckType` | нет | `Тент`/`Борт`, иначе из карточки груза |
| `loadWindow` | нет | до 40 символов, по умолчанию `08:00–12:00` |
| `startRate` | нет | **₽ за тонну**, не за рейс; `0` — ставку задаст логист |
| `mode` | нет | `AUCTION` (по умолчанию) или `CLOSED` |
| `comment` | нет | до 1000 символов |

Ответы: `201` — создан, `200` + `duplicate: true` — повтор, `400` — ошибка
данных, `401` — ключ, `503` — интеграция выключена. Номер платформы `Z-<n>`
выдаётся отдельно, ключ 1С хранится в `Request.onecRef`.

## 4. Чтение статуса

`GET /api/integration/1c/requests?onecRef=…` возвращает `status`/`statusRu`,
`winner` (перевозчик и ИНН), `rates.best`, `crew` (водитель, ТС, прицеп),
`etrn`. Поле `onecRef` есть у каждой строки реестра, поэтому 1С может
сопоставлять и выгрузку через `?since=`.

## 5. ЭТрН

`POST /api/integration/1c/etrn` подтверждает накладную. Титул Т1
подписывается в Диадоке; платформа хранит идентификаторы и статусы
(`SENT`, `SIGNED`). На стенде используется `mini-services/diadoc-mock` :3040.
Без `DIADOC_CLIENT_ID` интеграция выключена, остальная платформа работает.

## 6. Модули 1С

| Файл | Назначение |

| `docs/1c/orders-form-web-logistic.bsl` | форма «Заказы грузоотправителей»: кнопка «в Веб-Логистик», отправка рейсов, приём статусов |

После правки `docs/1c/simulator/index.html` скопируйте файл в
`public/1c-simulator/`.

## 7. Проверка

```bash
ONEC_URL=https://<домен> ONEC_API_KEY=<ключ> node docs/1c/onec-check.mjs
```

Скрипт проверяет связь, создаёт черновик «ПРОВЕРКА-…», повторяет отправку
(дубля быть не должно) и читает статус. Черновик затем удаляет логист.

## 8. Идемпотентность и ошибки

- Повтор `POST` с тем же `oneC_number` возвращает `200` и `duplicate: true`,
  данные первой отправки не меняются.
- `external_id`/`onecRef` — уникальные ключи; конфликт обрабатывается как
  повтор, а не как новая заявка.
- Ошибки валидации возвращают понятный текст на русском, чтобы модуль 1С мог
  показать его пользователю.
- Реестр `?since=` отдаёт изменения после указанной метки; 1С хранит свою
  метку и не теряет записи при обрыве.
