# Платформа «АЭМЗ Поток»

Платформа — ядро системы: Next.js 16 App Router, React 19, Prisma, SQLite.
Один процесс :3000 отдаёт интерфейс, REST API и встроенную диспетчерскую
`/kontur`.

## 1. Роли

| Роль | Что видит | Права |
|---|---|---|
| `admin` | всё | пользователи, шаблоны доступа, настройки, прямой просмотр БД, журналы |
| `logist` | заявки, торги, документы, реестр, отчёты, «Контур» | публикация, назначение победителя, сверка, рейсы |
| `carrier` | свой кабинет | ставки, свои заявки, экипаж, документы, ЭДО |

Права — гранулярные: `section:*` (раздел) и `own:*` (только свои объекты).
Шаблоны доступа (`AccessTemplate`) задают набор, `PermException` — точечные
исключения. Проверка выполняется на сервере; UI лишь скрывает недоступное.

## 2. Разделы

| Раздел | Назначение |
|---|---|
| Дашборд | сводка по заявкам, рейсам, документам, событиям |
| Заявки | создание, черновики, публикация, торги, назначение, статусы |
| Кабинет перевозчика | доступные заявки, ставки, экипаж, документы, ЭДО |
| Сверка документов | очередь проверки, вердикты OCR, ручное решение |
| Реестр рейсов | рейсы, статусы, выгрузка в 1С |
| Отчёты | Excel/DOCX, экспорт реестров и статистики |
| Справочники | перевозчики, водители, ТС, прицепы, грузы, фото |
| Поддержка | обращения и переписка |
| Администрирование | пользователи, доступы, настройки, журналы, БД |
| «Контур 1С» | собственный парк, планирование, мониторинг |

## 3. Жизненный цикл заявки

```
DRAFT
  │ публикация (логист)
  ▼
PUBLISHED ── ставки/фикс ──► AWARDED
  │                            │ исполнитель назначает экипаж и грузит документы
  │                            ▼
  │                        DOCS_REVIEW ── OCR + сверка
  │                            │ PASSED
  │                            ▼
  │                        AT_LOGIST ── подтверждение логистом
  │                            ▼
  └──────────────────────► CONFIRMED ── рейс/реестр/1С ──► CLOSED
```

- `FIXED` — фиксированная ставка, заявку забирает первый подходящий;
- `AUCTION` — торги вниз, победитель определяется по лучшей ставке;
- `CLOSED` — закрытая заявка для выбранного перевозчика;
- `QUARANTINE` — подозрительные документы/данные, требуется ручное решение.

Каждое действие пишет `Event`, при необходимости — `Notification` и
`PlatformLog`, затем отправляет `platform:update` в WS-шину.

## 4. Документы и нейропроверка

Перевозчик загружает паспорт, регистрацию, ВУ, СТС и М-2. Браузер сжимает
фото (2400 px, JPEG 92%), платформа сохраняет `dataUri` и отправляет его в
OCR-шлюз. `src/lib/verify.ts` сравнивает прочитанные поля с заявкой и выносит
`PASSED`, `REUPLOAD`, `REJECTED` или `MANUAL`. Логист видит причину и может
подтвердить вручную. Подробно — [ocr.md](ocr.md).

## 5. API

Основные группы (все — под `/api`):

| Группа | Маршруты |
|---|---|
| Авторизация | `auth/login`, `auth/logout`, `auth/me` |
| Заявки | `requests`, `requests/[id]`, `requests/[id]/action`, `documents`, `files`, `verify`, `bulk-assign` |
| Справочники | `directory`, `directory/bulk`, `directory/photos`, `suggest` |
| Водители/ТС | `drivers/intake`, `vehicles/intake` |
| Документы | `documents/check`, `ocr/status`, `ocr-jobs` |
| Отчёты | `reports`, `reports/excel`, `reports/docx`, `reports/export` |
| ЭДО | `edo` |
| 1С | `integration/1c/{ping,info,requests,etrn,dictionaries}` |
| Админ | `admin/{users,access,db,files,nn}`, `settings`, `platform-log` |
| Служебные | `architecture/status`, `driver-app/status`, `events`, `notifications`, `map-tile` |

Маршруты 1С защищены `X-API-Key` (`ONEC_API_KEY`), остальные — сессией.
Файлы отдаются по токену с проверкой доступа: `files/[kind]/[id]`.

## 6. Уведомления и real-time

- `Notification` — внутренние уведомления с непрочитанными;
- WS-шина `mini-services/ws-service` (:3003) рассылает `platform:update`
  после изменений; браузер подписывается на каналы пользователя/роли;
- при недоступности шины интерфейс обновляется по действию и поллингу;
- фоновая сверка торгов (`AUCTION_SWEEP_SEC`) закрывает истёкшие аукционы.

## 7. Отчёты и выгрузки

`xlsx` и `docx` формируются на сервере, `@resvg/resvg-js` и `sharp` вынесены
из бандла как нативные модули. Реестр рейсов и статусы уходят в 1С через
`/api/integration/1c/*`; ЭТрН — в Диадок.

## 8. Конфигурация

Все секреты — в `.env`/`.env.local` (см. `.env.example`): `DATABASE_URL`,
`AUTH_SECRET`, `ONEC_API_KEY`, `OCR_*`, `DIADOC_*`, `WS_*`. Без
`ONEC_API_KEY` маршруты 1С отвечают `503`; без `DIADOC_CLIENT_ID` ЭДО
выключено, остальная платформа работает.

## 9. Ограничения

- SQLite рассчитан на один узел; горизонтальное масштабирование не
  поддерживается.
- Платформа не хранит подписанные ЭТрН — только ссылки и статусы.
- OCR не является юридически значимой проверкой: финальное решение принимает
  логист.
