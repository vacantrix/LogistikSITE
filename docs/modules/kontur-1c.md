# «Контур 1С» и собственный парк

«Контур 1С» — рабочее место логиста/диспетчера для собственного парка АЭМЗ:
заявки из 1С и ATI.SU, планирование, занятость, рейсы, назначение водителя и
ТС, GPS-мониторинг, маршруты, чат, справочники и журнал.

В production это маршрут `/kontur` внутри платформы :3000. Таблицы лежат в
общей `db/combat.db` с префиксом `Dispatch` (схема `prisma/kontur.prisma`).
Отдельная копия в `driver/kontur-1c/` — автономный стенд и историческая
реализация; production-путём она не является.

## 1. Production-режим (`/kontur`)

```
1С:ERP ──POST /kontur/api/1c/orders──► Order (Dispatch)
ATI.SU ──/kontur/api/atisu/*──────────► Order / AtiDeal
логист ──/kontur──────────────────────► планирование и рейсы
```

| Раздел | Что делает |
|---|---|
| Заявки | приём, фильтры, «Провести», отмена, причины |
| Планирование | занятость водителей и ТС, план на день |
| Рейсы | `Trip` + `Leg`, статусы, назначение, завершение |
| Мониторинг | онлайн-статус, GPS-точки, трек на карте |
| Справочники | водители, ТС, прицепы, контрагенты, точки |
| Журнал | `AuditLog`, события, обмен с 1С |
| Отчёты | выгрузки по рейсам и занятости |

Ключевые API (все под `/kontur/api`):

- `1c/orders`, `1c/events`, `1c/ack` — обмен заявками и подтверждениями;
- `atisu/{loads,deals,market,trucks,status,backhaul,dictionaries}` — ATI.SU;
- `orders`, `plan-entries`, `bindings`, `devices`, `match` — планирование;
- `trip/[id]`, `trip/[id]/route-link` — рейс и маршрут из Яндекс.Карт;
- `monitor`, `driver/{trips,sync,telemetry}` — мониторинг и модуль водителя;
- `logist/{composition,correction}`, `review`, `call` — рабочие действия;
- `state`, `outbox`, `directory`, `files`, `demo/reset` — служебные.

## 2. Рейс и маршрут

1. Заявка приходит из 1С/ATI.SU или создаётся вручную.
2. Логист проводит её: создаётся `Trip` и два `Leg` (погрузка/выгрузка) в
   одной транзакции.
3. Назначаются водитель и ТС; проверяется занятость (`VehicleBinding`,
   `PlanEntry`).
4. Логист вставляет ссылку Яндекс.Карт в `route-link`; платформа сохраняет
   точную геометрию и параметры (см.
   [../integrations/yandex-routes.md](../integrations/yandex-routes.md)).
5. `driver-bridge.ts` отправляет снимок рейса в модуль водителя.
6. Водитель отмечает выезд, погрузку, выгрузку, завершение; события
   возвращаются в «Контур» и журнал.

Статусы рейса: `planned` → `assigned` → `in_progress` → `completed`
(плюс `cancelled`). Плечо хранит адреса, окна, контакты, геометрию и
фактические отметки.

## 3. ATI.SU

Стенд поддерживает поиск грузов, сделки, транспорт, статусы и справочники.
В демо-режиме возможен `stub`; в production ключи ATI.SU задаются в окружении
«Контура». Обмен идемпотентен по внешнему идентификатору сделки.

## 4. Автономный стенд `driver/kontur-1c`

Историческая реализация, которая архитектурно повторяет 1С: справочники,
документы с нумерацией и проведением, регистры, журнал, план обмена.
Поднимает собственный Next.js на :3001 (basePath `/kontur`), приложение
водителя на :3002 и роутер на :3000.

```bash
cd driver/kontur-1c
bun install
bun run db:push
bun run db:seed
bun run dev          # http://localhost:3001/kontur
```

Что внутри:

- `src/app/api/1c/orders` — HTTP-сервис «1С»: список заявок и обратный канал
  (`ACCEPT`, `PRETRIP_STEP`, `START_ROUTE`, `COMPLETE_TRIP`);
- `src/app/api/driver/v1/*` — шина `pull`/`push`/`marks`/`traffic`;
- `src/app/api/office/*` — API рабочих мест (заявки, рейсы, каталог, чат,
  журнал, файлы, маршрут);
- `src/lib/1c/*` — доменные сервисы: нумератор, заявка, назначение, отмена,
  действия водителя, разбор `rtext`;
- `src/lib/bus/*` — применение push-операций, журнал, снимки, пробки;
- `src/components/workspace/*` — 8 экранов офиса с поллингом 5 с.

Демо-водитель: `X-Driver-Id: 06c075d1-3088-45f2-a7ae-090e8c355447`
(Иванов С. П.). Демо-заявки: 1067 `ASSIGNED`, 1071/1074 `DISPATCH`, три
`DONE`.

Стенд полезен для проверки сквозного потока «заявка → диспетчер → водитель»
без рабочей 1С. При подключении реальной 1С слой эмуляции заменяется
коннектором к HTTP-сервисам, контракты и клиент не меняются.

## 5. Отношение к платформе

| | Production `/kontur` | Автономный `driver/kontur-1c` |
|---|---|---|
| Порт | 3000 | 3001 (+ водитель 3002, роутер 3000) |
| База | `db/combat.db`, `Dispatch*` | `driver/kontur-1c/db/custom.db` |
| Вход | платформа, единый домен | отдельный стенд |
| Статус | основной | legacy / демо |

Не запускайте оба «Контура» на одних портах одновременно. Для production
используйте `publish/start-all.ps1`; автономный стенд — только вручную.
