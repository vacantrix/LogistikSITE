# Безопасность

## 1. Модель

- Платформа — единственный источник бизнес-правил и прав.
- Все внутренние сервисы слушают `127.0.0.1`; наружу открыт только Caddy :443.
- Водитель видит только свой модуль и свои заявки.
- OCR не выносит данные в облако: модели и фото — на серверах АЭМЗ.

## 2. Секреты

| Секрет | Где | Правило |
|---|---|---|
| `AUTH_SECRET` | `.env.local` | ≥32 символа, уникальный, не в git |
| `ONEC_API_KEY` | `.env.local` + 1С | ≥24 символа, сравнение за постоянное время |
| `OCR_SERVICE_TOKEN` | платформа/шлюз/движок | общий, только localhost |
| `DIADOC_CLIENT_SECRET`, `DIADOC_REFRESH_TOKEN` | `.env.local` + БД | ротация, не логировать |
| `WS_NOTIFY_TOKEN` | платформа/WS | подпись служебных событий |
| `DRIVER_APP_INGEST_TOKEN` | платформа/модуль | подпись ingest рейса |
| пароли демо-стенда | `publish/config.ps1` | только демо, ротировать при production |

Правила:

- `.env`, `.env.local`, `publish/credentials.local.txt`, `*.pem` — в
  `.gitignore`;
- в репозитории только `.env.example` без значений;
- секреты не пишутся в логи, не попадают в скриншоты и чат;
- при подозрении на утечку — ротация и проверка истории git.

## 3. Аутентификация и права

- Пароли — scrypt-хеши, не обратимое шифрование.
- Сессия — подписанная HttpOnly-кука; для API — Bearer.
- Права `section:*` и `own:*`, шаблоны `AccessTemplate`, исключения
  `PermException`; проверка на сервере в каждом маршруте.
- Админ может открыть профили и доступы; не-админ получает отказ — это
  проверяет `verify-stack.ps1`.
- Basic Auth Caddy — дополнительный периметр для `/kontur` и `/api/1c/*`,
  не замена учётной записи платформы.

## 4. Файлы и персональные данные

- Документы и фото — в `upload/`, не в git.
- Доступ к файлу — по токену с проверкой прав (`files/[kind]/[id]`).
- Реальные паспорта, ВУ, СТС, доверенности нельзя коммитить, пересылать в
  чат или использовать в тестах.
- `tools/ocr-probe/samples_real/`, `out_real/`, `requests/` — локальные и
  исключены `.gitignore`.
- Синтетические образцы содержат вымышленные данные и штамп «ОБРАЗЕЦ».
- Логи не должны содержать `dataUri` документов и полные номера.

## 5. Сеть

- Caddy — единственный процесс, смотрящий в интернет.
- Порты 3000, 3003, 3020, 3031, 3040, 3102, 8080, 8090 — только loopback.
- `/api/driver/*` публичный (APK), но защищён `X-Driver-Id` и токеном
  ingest; `/api/1c/*` — Basic Auth + `X-API-Key`.
- HSTS, `X-Content-Type-Options`, `Referrer-Policy` включены в Caddy.
- Лимит тела запроса — 50 MB.

## 6. OCR

- Шлюз и движок недоступны снаружи.
- Токен `X-OCR-Token` обязателен, если задан `OCR_SERVICE_TOKEN`.
- Модели и venv не коммитятся.
- При недоступности OCR документ остаётся на проверке; фиктивный вердикт не
  подставляется.

## 7. APK

- Пилот подписан debug-ключом; для production нужна отдельная подпись и
  хранение ключа вне репозитория.
- `versionCode` увеличивается при каждом релизе; старые APK не публикуются.
- Публичная ссылка `/dl/Drivemobile.apk` отдаётся с `Cache-Control: no-cache`.
- APK не содержит секретов; адрес API задаётся конфигурацией сборки.

## 8. Демо-стенд

На стенде есть демонстрационные учётные записи и пароли (в `publish/config.ps1`
и на экране входа). Они **не являются production-секретами**:

- не используйте их в боевом контуре;
- перед production смените пароли, `DRIVER_APP_INGEST_TOKEN`, Basic Auth;
- ограничьте доступ к `/kontur` и `/api/1c/*`;
- не публикуйте `.env` и `credentials.local.txt`.

## 9. Зависимости и обновления

- `next` обновляется security-патчами (`experimental.agentUpgrade`).
- Перед обновлением — резервная копия баз и `upload/`.
- Проверяйте `npm audit`/`bun audit` и фиксируйте версии.
- Не добавляйте необслуживаемые форки и бинарники без источника.

## 10. Инцидент

1. Остановить публичный доступ (`publish\stop-caddy.ps1`) при утечке.
2. Ротировать затронутые секреты.
3. Проверить `PlatformLog`, `AuditLog`, логи Caddy.
4. Восстановить данные из резервной копии при порче.
5. Зафиксировать инцидент в `worklog.md` без секретов и ПДн.
