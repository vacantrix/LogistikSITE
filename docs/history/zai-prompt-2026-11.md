Последняя версия — ветка `main` (она же `fix/ui-review`): в ней твой Task 83 («Автозаполнение», две нейросети) слит с доработками после него. Разверни её у себя и проверь. ## 1. Обновление и запуск
1. `git fetch origin && git checkout main && git pull --ff-only`. Если локально есть свои незакоммиченные правки — сначала покажи их мне, не затирай.
2. Зависимости: `bun install` (или `npm install`).
3. `.env` / `.env.local` по образцу `.env.example`. Секреты не коммить и не выводи в лог.
4. База: `npm run db:push` — схема изменилась (у водителя удалены поля ВУ: license, licenseTill, categories), флаг `--accept-data-loss` уже в скрипте. Затем `npm run db:generate`. Если база новая — заполни её сидом, как раньше.
5. OCR (`mini-services/paddle-ocr`): venv с версиями из `requirements.txt` (paddleocr 3.7.0, paddlex 3.7.2, paddlepaddle 3.3.1), запуск `python server.py` (127.0.0.1:3031). На стенде с 4 ГБ задай `OCR_LOW_MEMORY=1`: включится твой режим из Task 83 — процесс на документ, кадр 736 px. Без переменной режим включается сам, если свободной памяти меньше 6 ГБ. При запасе памяти обе модели держатся тёплыми.
6. Остальные сервисы: шина `npm run ws` (порт 3003, `NEXT_PUBLIC_WS_URL`), имитация Диадока `node mini-services/diadoc-mock/server.mjs` (порт 3040, переменные `DIADOC_*`), сайт `npm run dev` (порт 3000).

## 2. Что изменилось после Task 83 (не откатывай)
- **ВУ убрано отовсюду**: документ, поля водителя, колонки справочника, Excel-шаблон, ЭТрН, выгрузки 1С, сиды. Платформа считает ВУ неизвестным документом. Не возвращай.
- **Проформа водителя**: даты — маска и календарь; адрес регистрации и место рождения — подсказки из OpenStreetMap (Photon) через `/api/suggest` и выбор точки на карте; «Кем выдан» — формулировки по региону адреса и значения из базы; должность — встроенный вариант «Водитель». Свой геокодер — переменная `GEOCODER_URL`.
- **Фото**: загрузка по шагам (1 → 2) с кружком прогресса, в том числе при замене (`photo-steps.tsx`). Фото до 2400 px и 4,5 МБ не пересжимаются. Раньше сжатие до 1280 px, JPEG 80 % ломало чтение паспорта. При замене фото очищаются поля, прочитанные со старого снимка, если их не правили вручную.
- **Паспорт**:
  - машиночитаемые строки (PNRUS…): по ним определяется документ, номер, даты и код берутся с проверкой контрольных цифр, ФИО сверяется с бланком (таблицы МВД и ICAO), одна неверная буква исправляется по строке;
  - повторный проход ×1,5 точной моделью, если документ не узнан или поля не дочитаны;
  - «Кем выдан» читается со страницы с фото; гражданство «РФ» ставится автоматически;
  - исправления «ФОП/ТОР» → «ГОР.», «JI» → «Л»;
  - старые штампы регистрации: дата словами, адрес по подписям «Рег-н / Пункт / Улица / Дом / Кв»;
  - перепутанные страницы паспорта сами встают в свои слоты;
  - серия и номер сверяются между страницей с фото и регистрацией; если не совпали — регистрация отклоняется, адрес из неё не подставляется.
- **СТС**: цвет читается с лицевой стороны и подставляется в карточки ТС и прицепа.
- **OCR-сервис**: временные файлы в PNG без потерь (двойное JPEG-сжатие размывало подписи); точная модель добирает пустые поля лёгкой.
- **Интерфейс**: подсказки только по наведению (`InfoTip`/`WithTip` в `common.tsx`) — постоянных поясняющих надписей не добавляй. Знак LogistikSITE: `public/logo-mark.svg`, `favicon.ico`, `apple-touch-icon.png`, компонент `LogoMark`; в шапке — оранжевая инверсия.
- **ЭДО** — только Диадок (1С в интерфейсе не показываем); роль исполнителя (перевозчик / экспедитор) в «Справочниках».
