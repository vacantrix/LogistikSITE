# Интеграция с 1С: черновики заявок из 1С

Двусторонняя схема:

1. **1С → платформа.** Кнопка в документе 1С отправляет `POST /api/integration/1c/requests`, и на платформе появляется **черновик** заявки (`DRAFT`) с автором «1С (интеграция)».
2. **Логист** видит его в «Черновиках заявок», при необходимости правит, задаёт срок торгов и публикует.
3. **Платформа → 1С.** 1С забирает статус, победителя, ставку и экипаж: `GET /api/integration/1c/requests?onecRef=…` (или весь реестр через `?since=`).
4. **ЭТрН.** 1С подтверждает накладную через `POST /api/integration/1c/etrn`, как и раньше.

Авторизация — заголовок `X-API-Key` со значением `ONEC_API_KEY` из `.env` сервера (не короче 24 символов). Без переменной все маршруты `/api/integration/1c/*` отвечают `503`.

## POST /api/integration/1c/requests

```json
{
  "oneC_number": "ЗП-0012 от 28.10.2026",
  "fromPoint": "Краснодарский край, г. Абинск, ул. Промышленная, д. 4",
  "toPoint": "г. Санкт-Петербург, Канонерский остров, д. 45",
  "cargo": "Перевозка готовой продукции - арматура",
  "tonnage": 20.5,
  "truckType": "Борт",
  "loadDate": "2026-10-30",
  "loadWindow": "09:00–18:00",
  "startRate": 4200,
  "mode": "AUCTION",
  "comment": "Срочная доставка"
}
```

| Поле | Обяз. | Что принимается |
|---|---|---|
| `oneC_number` | да | Ключ документа 1С, до 100 символов. Номера 1С повторяются каждый год, поэтому модуль формы шлёт «номер от даты». Повтор с тем же ключом **не создаёт дубль**. |
| `fromPoint`, `toPoint` | да | Адреса текстом, до 300 символов. Сохраняются как есть, со справочником точек не сводятся. |
| `cargo` | да | Наименование груза. Сравнивается со справочником грузов без учёта регистра, «ё» и вида тире. Если такого груза нет, он **добавляется в справочник** (в ответе `cargoCreated: true`, запись в журнале событий). |
| `loadDate` | да | `ГГГГ-ММ-ДД`, `ГГГГ-ММ-ДДTчч:мм:сс` (так `ЗаписатьJSON` пишет тип Дата) или `ДД.ММ.ГГГГ`. Прошедшая дата отклоняется. |
| `tonnage` | нет | Тонны, `0 < x ≤ 200`. По умолчанию 20. |
| `truckType` | нет | `Тент` или `Борт` (регистр не важен). По умолчанию берётся из карточки груза. |
| `loadWindow` | нет | Строка до 40 символов. По умолчанию `08:00–12:00`. |
| `startRate` | нет | **₽ за тонну**, а не за рейс. `0` или не передавать: ставку задаст логист при публикации. |
| `mode` | нет | `AUCTION` (по умолчанию) или `CLOSED`. |
| `comment` | нет | До 1000 символов. Показывается исполнителю. |

Ответы:

| Код | Когда | Тело |
|---|---|---|
| `201` | черновик создан | `{ ok: true, data: { id, number, onecRef, status: "DRAFT", statusRu, cargo, createdAt, duplicate: false, cargoCreated } }` |
| `200` | документ уже отправлялся | то же, `duplicate: true` (данные первой отправки, черновик не меняется) |
| `400` | ошибка в данных | `{ ok: false, error: "понятный текст" }` |
| `401` / `503` | неверный ключ / интеграция выключена | `{ ok: false, error }` |

Номер заявки (`Z-<n>`) выдаёт платформа по своему правилу. Номер 1С хранится отдельно, в поле `Request.onecRef`.

## GET /api/integration/1c/requests?onecRef=…

Статус одного документа 1С: `data[0].status` / `statusRu`, `winner` (перевозчик и ИНН), `rates.best`, `crew` (водитель, ТС, прицеп), `etrn`. Поле `onecRef` есть у каждой строки реестра, так что 1С может сопоставлять и при выгрузке через `?since=`.

## Развёртывание на сервере

1. Подтянуть изменения и обновить схему БД: добавится одна необязательная колонка `Request.onecRef` с уникальным индексом, существующие данные не меняются.

   ```bash
   bun run db:push
   ```

2. Задать ключ в `.env` (пример генерации: `openssl rand -hex 24`):

   ```
   ONEC_API_KEY=<ключ не короче 24 символов>
   ```

3. Пересобрать и перезапустить платформу (`bun run build`, затем перезапуск сервиса).
4. Проверить обмен **без 1С** (ключ — тот же, что на сервере):

   ```bash
   ONEC_URL=https://<домен-платформы> ONEC_API_KEY=<ключ> node scripts/onec-check.mjs
   ```

   Скрипт делает те же запросы, что модуль 1С: проверку связи, создание черновика, повтор (дубля быть не должно) и чтение статуса. Каждый запуск создаёт черновик «ПРОВЕРКА-…», логист удаляет его в «Черновиках заявок».

Caddy (`Caddyfile`) пропускает все пути, кроме `?XTransformPort=…`, на Next.js `:3000`, так что `/api/integration/1c/*` доступен снаружи без правок.

## Подключение в 1С

Модуль формы: [`send-request-form-module.bsl`](send-request-form-module.bsl).

1. В форме документа создайте команды **«ОтправитьНаПлатформу»** и **«СтатусНаПлатформе»** и вынесите их кнопками.
2. Скопируйте модуль. В функции `ДанныеЗаявкиДляПлатформы()` сверьте имена реквизитов документа со своими.
3. В `АдресПлатформы()` и `КлючAPI()` укажите домен и ключ (в рабочей базе — через константы).

Что учтено в модуле:

- запросы выполняются на сервере: ключ не уходит на клиент, код работает и в веб-клиенте;
- несохранённый документ сначала записывается, потому что номер присваивается при записи;
- повторное нажатие не создаёт дубль: платформа отвечает `200`, и 1С сообщает, что документ уже отправлен;
- сертификат сервера проверяется по корневым сертификатам ОС (`СертификатыУдостоверяющихЦентровОС`);
- тело уходит в UTF-8 без BOM; ответ читается в `Соответствие`, чтобы ключи вроде `to` не ломали `ПрочитатьJSON`.
