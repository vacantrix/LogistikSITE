# Симулятор 1С на GitHub Pages

`index.html` — окно 1С:Предприятия (интерфейс «Такси») с документом «Заявка на перевозку». Страница отправляет на веб-платформу те же запросы, что модуль 1С (`docs/1c/send-request-form-module.bsl`), и позволяет показать интеграцию с любого компьютера без установки 1С.

Как в 1С:

- панель разделов, вкладки открытых окон, список «Заявки на перевозку» с отметкой проведённых;
- форма документа: подписи слева, жёлтая «Провести и закрыть», поля выбора ▾ / …, календарь, числа в формате 1С;
- проверка заполнения: красное подчёркивание пустых полей и панель «Сообщения:»;
- оповещения в правом нижнем углу, окна «1С:Предприятие» и вопрос «Сохранить изменения?».

Обмен с платформой:

| Действие в симуляторе | Запрос |
|---|---|
| **Провести** / **Провести и закрыть** | `POST /api/integration/1c/requests` — черновик заявки |
| **Статус на платформе** (в форме или в списке) | `GET /api/integration/1c/requests?onecRef=<номер от даты>` |
| **Ещё → Настройка обмена… → Проверить связь** | `GET /api/integration/1c/ping` |
| **Ещё → Журнал обмена…** | JSON, который ушёл, и ответ платформы |

Документы симулятора хранятся в браузере, как записи информационной базы. Номер (`Д123-000001`) присваивается при записи; префикс случайный, чтобы номера разных компьютеров не совпали.

## 1. Подготовка сервера платформы (один раз)

В `.env` на сервере:

```
ONEC_API_KEY=<ключ не короче 24 символов>
ONEC_CORS_ORIGINS=https://vacantrix.github.io
```

`ONEC_CORS_ORIGINS` — адрес сайта, с которого открыт симулятор: только схема и домен, без пути и слеша в конце. Для GitHub Pages пользователя `vacantrix` это `https://vacantrix.github.io`.

После правки `.env` перезапустите платформу.

Платформа должна открываться по **https**: страница GitHub Pages работает по https, и браузер не даст ей обратиться к http-адресу.

## 2. Включить GitHub Pages (один раз)

Отдельный репозиторий не нужен: Pages публикует папку `docs` самого LogistikSITE, а симулятор лежит в `docs/1c/simulator/`.

1. github.com → репозиторий **vacantrix/LogistikSITE** → **Settings** → **Pages** (меню слева).
2. В блоке **Build and deployment**:
   - **Source**: «Deploy from a branch»;
   - **Branch**: `main`, папка **`/docs`** → **Save**.

   Пока ветка `claude/1c-request-drafts` не влита в `main`, можно временно выбрать её — с той же папкой `/docs`.
3. Через 1–2 минуты вверху страницы **Pages** появится адрес сайта `https://vacantrix.github.io/LogistikSITE/`. Ход публикации виден во вкладке **Actions** («pages build and deployment»).
4. Симулятор открывается по адресу:

   ```
   https://vacantrix.github.io/LogistikSITE/1c/simulator/
   ```

Публикуется только папка `docs` (материалы 1С); код платформы и `.env` на сайт не попадают. Ключа в `index.html` нет: с ним читаются справочники с паспортными данными водителей, поэтому ключ вводится только на самой странице. Файл `docs/.nojekyll` нужен, чтобы GitHub отдавал файлы как есть.

## 3. Демонстрация

1. Откройте ссылку с адресом платформы в параметре:

   ```
   https://vacantrix.github.io/LogistikSITE/1c/simulator/?api=https://<домен-платформы>
   ```

   Откроется новая «Заявка на перевозку (создание)» с заполненными полями.
2. **Ещё → Настройка обмена с веб-платформой…**: введите API-ключ → **Проверить связь** → «Связь есть, ключ принят» → **ОК**. «Запомнить ключ в этом браузере» отмечайте только на своём компьютере. Если ключ не введён, окно откроется само при первом проведении.
3. Проверка заполнения: очистите «Адрес погрузки» и нажмите **Провести**. Поле подчеркнётся красным, внизу — «Поле "Адрес погрузки" не заполнено». Верните адрес.
4. **Провести и закрыть** → оповещение «Заявка отправлена на веб-платформу: № Z-…». В списке у документа отметка «проведён», номер и статус на платформе.
5. Двойной щелчок по строке → **Провести** ещё раз → «Заявка уже на веб-платформе… Повторно не создана». Так показывается защита от дублей.
6. На платформе под логистом: **Черновики заявок** → заявка от «1С (интеграция)» → **Опубликовать**.
7. В симуляторе: строка списка → **Статус на платформе** → «На площадке»; после торгов — перевозчик, лучшая ставка, экипаж, ЭТрН.

После демонстрации удалите тестовые черновики в «Черновиках заявок».

## Если не работает

| Сообщение | Что проверить |
|---|---|
| «Браузер не получил ответ от платформы» | Адрес платформы; `ONEC_CORS_ORIGINS` совпадает с адресом из подсказки на странице, платформа перезапущена; платформа на https. |
| «Ошибка 401» | Ключ не совпадает с `ONEC_API_KEY`. |
| «Ошибка 503» | На сервере не задан `ONEC_API_KEY`. |
| «Ошибка 400: …» | Текст ошибки говорит, какое поле поправить (дата в прошлом, тип ТС и т. п.). |

Проверка сервера без браузера:

```bash
curl -i -X OPTIONS https://<домен>/api/integration/1c/requests -H "Origin: https://vacantrix.github.io" -H "Access-Control-Request-Method: POST" -H "Access-Control-Request-Headers: content-type,x-api-key"
```

В ответе `204` должен быть заголовок `access-control-allow-origin: https://vacantrix.github.io`.
