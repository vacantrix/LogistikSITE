# Симулятор 1С на GitHub Pages

`index.html` повторяет форму «Заказы грузоотправителей» конфигурации «АЭМЗ / Учет металла» (1С:Предприятие 8.3, интерфейс «Такси»). Рядом с жёлтой кнопкой «Путевые листы» стоит новая **«в Веб-Логистик»**: отмеченные рейсы уходят на веб-платформу черновиками заявок, чтобы найти перевозчика через торги. Страница делает те же запросы, что модуль `docs/1c/orders-form-web-logistic.bsl` для настоящей формы, и показывает интеграцию с любого компьютера без 1С.

Что на форме:

- **Отбор:** период, транспортная компания, число машин и рейсов, вес машины (прокат 21 т, катанка 24 т).
- **Дерево заказов:** спецификация → пункт разгрузки → номенклатура (зелёные строки) с заказом ТС, «На вывоз» и «Остаток». **Заполнить** планирует рейсы по отмеченным строкам с учётом веса машины.
- **Рейсы:** п/п, даты погрузки и выгрузки, колонка **Веб-Логистик** (номер и статус на платформе), транспортная компания, ТС, прицеп, водитель, контрагент, заказчик, спецификация, пункт разгрузки, продукция.

Все компании, водители и номера ТС в симуляторе вымышленные.

Обмен с платформой:

| Действие в симуляторе | Запрос |
|---|---|
| **в Веб-Логистик** (по отмеченным рейсам) | `POST /api/integration/1c/requests` — черновик заявки на каждый рейс |
| **Еще → Обновить статусы Веб-Логистик** | `GET /api/integration/1c/requests?onecRef=<рейс>`; выбранный перевозчик и экипаж переносятся в рейс |
| **Еще → Настройка обмена… → Проверить связь** | `GET /api/integration/1c/ping` |
| **Еще → Журнал обмена…** | JSON, который ушёл, и ответ платформы |

Рейсы и статусы обмена хранятся в браузере. «Еще» в шапке формы → «Сбросить демо-данные» возвращает исходные рейсы.

## 1. Подготовка сервера платформы (один раз)

В `.env` на сервере:

```
ONEC_API_KEY=<ключ не короче 24 символов>
ONEC_CORS_ORIGINS=https://vacantrix.github.io
```

`ONEC_CORS_ORIGINS` — адрес сайта, с которого открыт симулятор: только схема и домен, без пути и слеша в конце. Для GitHub Pages пользователя `vacantrix` это `https://vacantrix.github.io`.

После правки `.env` перезапустите платформу.

Платформа должна открываться по **https**: страница GitHub Pages работает по https, и браузер не даст ей обратиться к http-адресу.

## 2. Включить GitHub Pages (один раз)

Отдельный репозиторий не нужен: Pages публикует папку `docs` самого LogistikSITE, а симулятор лежит в `docs/1c/simulator/`.

1. github.com → репозиторий **vacantrix/LogistikSITE** → **Settings** → **Pages** (меню слева).
2. В блоке **Build and deployment**:
   - **Source**: «Deploy from a branch»;
   - **Branch**: `main`, папка **`/docs`** → **Save**.

   Пока ветка `claude/1c-request-drafts` не влита в `main`, можно временно выбрать её — с той же папкой `/docs`.
3. Через 1–2 минуты вверху страницы **Pages** появится адрес сайта `https://vacantrix.github.io/LogistikSITE/`. Ход публикации виден во вкладке **Actions** («pages build and deployment»).
4. Симулятор открывается по адресу:

   ```
   https://vacantrix.github.io/LogistikSITE/1c/simulator/
   ```

Публикуется только папка `docs` (материалы 1С); код платформы и `.env` на сайт не попадают. Ключа в `index.html` нет: с ним читаются справочники с паспортными данными водителей, поэтому ключ вводится только на самой странице. Файл `docs/.nojekyll` нужен, чтобы GitHub отдавал файлы как есть.

## 3. Демонстрация

1. Откройте ссылку с адресом платформы в параметре:

   ```
   https://vacantrix.github.io/LogistikSITE/1c/simulator/?api=https://<домен-платформы>
   ```

2. Внизу у рейсов 1–3 транспорт уже есть (своя «АЭМЗ ООО» и привлечённая ТК), у рейсов 4–6 — нет. Для них и нужен перевозчик.
3. По желанию — планирование: отметьте строки номенклатуры вверху → **Заполнить**. Добавятся рейсы без транспорта по весу машины.
4. **Отметить N** → 3 → **ОК**: отмечены рейсы без транспорта.
5. **в Веб-Логистик** → в окне — список рейсов, грузы и вес → **Отправить**. При первой отправке откроется настройка: введите API-ключ, **Проверить связь** → **ОК** и нажмите кнопку ещё раз.
6. Оповещение «Создано черновиков: 3 (№4 → Z-…)». В колонке **Веб-Логистик** — «Z-… · Черновик».
7. Повторно **в Веб-Логистик** для тех же рейсов → «Уже были на платформе» — дублей нет.
8. На платформе под логистом: **Черновики заявок** → заявки от «1С (интеграция)» → **Опубликовать**. После торгов (или «Предложить напрямую») заявка уходит перевозчику.
9. В симуляторе: **Еще → Обновить статусы Веб-Логистик** → статус «Перевозчик выбран», в рейсе появляется транспортная компания, после назначения экипажа — водитель, ТС и прицеп.
10. Теперь по рейсу можно сформировать **«Путевые листы»** (в демо отмечается колонка «Н»).

После демонстрации удалите тестовые черновики в «Черновиках заявок».

## Если не работает

| Сообщение | Что проверить |
|---|---|
| «Браузер не получил ответ от платформы» | Адрес платформы; `ONEC_CORS_ORIGINS` совпадает с адресом из подсказки на странице, платформа перезапущена; платформа на https. |
| «Ошибка 401» | Ключ не совпадает с `ONEC_API_KEY`. |
| «Ошибка 503» | На сервере не задан `ONEC_API_KEY`. |
| «Ошибка 400: …» | Текст ошибки говорит, какое поле поправить (дата в прошлом, тип ТС и т. п.). |

Проверка сервера без браузера:

```bash
curl -i -X OPTIONS https://<домен>/api/integration/1c/requests -H "Origin: https://vacantrix.github.io" -H "Access-Control-Request-Method: POST" -H "Access-Control-Request-Headers: content-type,x-api-key"
```

В ответе `204` должен быть заголовок `access-control-allow-origin: https://vacantrix.github.io`.
