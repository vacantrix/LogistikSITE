# АЭМЗ Логистика

Закрытая веб-платформа завода АЭМЗ для работы с привлечённым транспортом: площадка
заявок с торгами на понижение, кабинет перевозчика (ставки → экипаж → документы),
нейропроверка документов на PaddleOCR, сверка логистом, реестр рейсов, ЭДО (ЭТрН,
Диадок) и двусторонняя интеграция с 1С.

Всё работает на одном маршруте `/`: роль берётся из сессии, разделы — вкладки под роль.

---

## 1. Как устроена система

**Веб-платформа поднимается на сервере АЭМЗ. Фотографии и файлы загружаются
на серверы АЭМЗ. Распознавание работает на серверах АЭМЗ — сейчас показательно
на отдельном GPU-ПК (временный стенд, подбор по объёму VRAM).**

```
   ПОЛЬЗОВАТЕЛИ И СИСТЕМЫ (несколько человек работают одновременно)
   ┌──────────────────┐  ┌──────────────────┐  ┌───────────────────┐
   │ Логист / админ   │  │ Перевозчик       │  │ 1С:ERP (шина)     │
   │ браузер: торги,  │  │ браузер: заявки, │  │ X-API-Key: заказы,│
   │ сверка, чаты     │  │ фото, обращения  │  │ статусы, ЭТрН     │

```

**Порты и сервисы**

| Сервис | Порт | Код | Назначение |
|---|---|---|---|
| Веб-платформа | 3000 | `src/` | Единственная точка входа: UI + REST API |
| Real-time шина | 3003 | `mini-services/ws-service` | `platform:update` после записей в БД — вкладки обновляются у всех |
| OCR-шлюз | 3020 | `mini-services/ocr-service` | Приём dataUri → передача движку по X-OCR-Token; слушает только 127.0.0.1 |
| Нейросеть PaddleOCR | 3031 | `mini-services/paddle-ocr` | Python-движок нейросети на серверах АЭМЗ (сейчас показательно на отдельном GPU-ПК) |
| Диадок-мок | 3040 | `mini-services/diadoc-mock` | Стенд ЭДО: статусы ЭТрН SENT/SIGNED |

Клиент всегда ходит по относительным путям; на другой порт указывает query-параметр
`?XTransformPort=` (шлюз Caddy), например `io('/?XTransformPort=3003')`.

**Многопользовательский сценарий.** Несколько перевозчиков могут подавать документы
одновременно: все фото попадают в одну общую очередь нейросети. Машина берёт в работу
не больше «максимума фото в обработке» (настройка подбирается под VRAM машины
нейросети), остальные честно ждут своего хода — порядок один для всех, без приоритетов.
Разовая подача перевозчика — до 20 фото; следующий заход продолжает очередь.

## 2. Пропуск документов: путь скана

1. **Загрузка.** Перевозчик прикладывает сканы (JPG/PNG/WebP/PDF) в «Мои заявки»
   (вручную или через «Автозаполнение» — до 20 фото за раз, платформа сама раскладывает
   их по недостающим документам). Клиент сжимает фото до 1280 px (canvas), сервер
   хранит его в БД на сервере АЭМЗ (таблица `Document`, поле dataUri).
2. **Отправка на проверку.** `POST /api/requests/[id]/verify` (комплект заявки) или
   intake-маршруты (карточки водителя/ТС). Проверяются только документы в статусе `PENDING`;
   за один заход — до 20 фото, остаток ждёт следующего захода.
3. **Общая очередь** (`src/lib/ocr-service.ts`). Платформа читает настройки нейросети
   (таблица `Setting`, раздел админа «Нейросеть») и:
   - берёт скан из **кэша повторов** по хэшу содержимого (`nnCacheMin`), если он уже читался;
   - **сжимает фото** перед отправкой в нейросеть (`nnMaxSide`, sharp);
   - отправляет в шлюз — одновременно не больше `nnParallel` фото («максимум фото
     в обработке», подбирается под VRAM); лишние ждут в очереди;
   - ждёт не дольше `nnTimeoutSec`, иначе документ остаётся «на проверке» и сбой пишется в журнал.
4. **Шлюз** (`mini-services/ocr-service`) передаёт скан движку нейросети на серверах АЭМЗ
   (заголовок `X-OCR-Token`).
5. **PaddleOCR** читает документ по шаблону полей (`PASSPORT_PHOTO`, `PASSPORT_REG`,
   `STS`, `POA`, `REQUEST_DOC`; на движке есть ещё `LICENSE`): возвращает качество фото,
   поля, уверенности, вид документа. Одна сильная модель (PP-OCRv5 server_det + mobile_rec).
6. **Сверка и правила** (`src/lib/verify.ts`): качество ниже `minQuality` → «перезагрузить»;
   каждое поле сверяется с заявкой/карточкой; уверенность и подтверждения решают вердикт:

| Вердикт | Когда | Кто решает |
|---|---|---|
| `PASSED` | поля уверенные, правила пройдены | нейросеть |
| `REUPLOAD` | низкое качество / не тот документ | нейросеть |
| `REJECTED` | уверенное расхождение с заявкой | нейросеть, порог `confReject` |
| `MANUAL` | неоднозначность | логист на «Проверке документов» |

Пороги `confReupload / confReject / confAuto / minQuality` и правила — в разделе
админа **«Настройки»**; скорость и надёжность конвейера — в разделе **«Нейросеть»**
(в том числе «максимум фото в обработке» под VRAM). Оба применяются сразу, без перезапуска.

**Нейросеть недоступна?** Проверка честно вернёт «сервис распознавания недоступен»,
документ останется `PENDING`, повтор — той же кнопкой после восстановления узла;
очередь не теряет места.

## 3. Роли и сценарии

| Роль | Логины | Разделы |
|---|---|---|
| Администрация | `admin` | всё контура логиста + «Нейросеть», «Настройки», «Профили и доступы», «База данных», «Архитектура» |
| Логист | `logist1`, `logist2` | Площадка с торгами, Черновики (в т.ч. из 1С), Проверка документов, Реестры, Справочники, Отчёты, Журнал, ЭДО, Обращения |
| Перевозчик | `carrier-a` / `carrier-b` / `carrier-v` / `carrier-g` | Площадка, Мои заявки, Подать документы, Назначение экипажей, Справочники, ЭДО, Обращения |

Жизненный цикл заявки:
`DRAFT → PUBLISHED → (ставки, перебитие) → AWARDED → экипаж → документы + нейропроверка →
DOCS_REVIEW → AT_LOGIST → CONFIRMED → ЭТрН/1С → CLOSED`.

Демо-вход: на экране входа есть блок «Демо-доступы» (показывается при заданном
`NEXT_PUBLIC_DEMO_PASSWORD`); пароль один на все учётки демо-контура.

## 4. Структура проекта

```
├── README.md                 ← этот файл: карта всего проекта

│   ├── app/                  маршруты и страницы                → src/app/README.md
│   │   ├── api/              REST API: заявки, документы, 1С…   → src/app/api/README.md
│   │   └── (страница /)      единый маршрут: сессия → вкладки
│   ├── components/

│   │   └── platform/         экраны платформы по ролям          → src/components/platform/README.md

│   ├── ocr-service/          OCR-шлюз :3020                     → mini-services/ocr-service/README.md

├── docs/                     материалы интеграции 1С            → docs/README.md
│   └── 1c/                   модули .bsl, симулятор, проверка   → docs/1c/README.md
├── public/                   статика: логотип, демо-сканы,      → public/README.md
│   └── 1c-simulator/         установленный симулятор 1С (/1c-simulator)
├── scripts/                  служебные скрипты (сиды, E2E,…)    → scripts/README.md
├── tests/                    проверки окружения                 → tests/README.md
```

### Ключевые файлы серверной логики (`src/lib/`)

| Файл | Роль |
|---|---|
| `verify.ts` | движок автопроверки: качество → тип → распознавание → сверка → вердикт |
| `ocr-service.ts` | пул к OCR-шлюзу: parallel/timeout/cache/maxSide из настроек нейросети |
| `nn.ts` | настройки нейросети (чтение, валидация, кэш 5 с, сжатие sharp) |
| `requests.ts` | заявки и торги: транзакции SQLite, финализация истёкших тендеров |
| `auth.ts` | сессии (Bearer + кука), роли, проверка доступа |
| `permissions.ts` / `perm-catalog.ts` | гранулярные права по должностям |
| `onec.ts` | слой 1С: ключ (сравнение за постоянное время), CORS, русские статусы |
| `notify.ts` / `notify-users.ts` | события → шина WS + адресные уведомления |
| `settings.ts` | пороги уверенности и правила проверки |
| `diadoc/*` | клиент Диадока и титул ЭТрН Т1 |

### Модель данных (`prisma/schema.prisma`)

Блоки: люди и компании (`User`, `Carrier`, `Driver`), техника (`Truck`, `Trailer`),
торги и рейсы (`Request`, `Bid`, `Event`), документы (`Document`, `RequestFile`),
ЭДО (`EdoDocument`, `DiadocState`), служебное (`Setting`, `Notification`,
`PlatformLog`, `AccessTemplate`, `RolePerm`).

## 5. Запуск

```bash
bun install
bun run db:push        # схема БД (db/custom.db)
bun run auth:seed      # учётные записи (идемпотентно)
bun run dev            # платформа :3000
```

Нейросеть (иначе документы остаются «на проверке» до ответа сервиса):

1. Движок нейросети на серверах АЭМЗ: инструкция `mini-services/paddle-ocr/README.md` → `:3031`
   (сейчас показательно развёрнут на отдельном GPU-ПК — временный стенд; адрес для шлюза — в `PADDLE_OCR_URL`).
2. Шлюз: `cd mini-services/ocr-service && bun install && bun run dev` → `:3020`.

Real-time шина: `cd mini-services/ws-service && bun install && bun run dev` → `:3003`.

Проверка контура без браузера: `scripts/README.md` (E2E-скрипт гоняет скан
платформа → шлюз → нейросеть и замеряет время).

### Переменные окружения (`.env`)

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | файл SQLite |
| `ONEC_API_KEY` | ключ шины 1С (без него `/api/integration/1c/*` отвечает 503) |
| `NEXT_PUBLIC_DEMO_PASSWORD` | показать демо-доступы на экране входа (только стенд) |
| `OCR_SERVICE_URL` / `OCR_SERVICE_TOKEN` | адрес/токен OCR-шлюза для платформы |
| `PADDLE_OCR_URL` / `PADDLE_OCR_TOKEN` | адрес узла нейросети АЭМЗ для шлюза |
| `DEMO_SAMPLES` | `1` — разрешить имитацию распознавания SVG-заглушек (стенд) |

## 6. Инструменты администратора

| Раздел | Что делает |
|---|---|
| «Нейросеть» | пропуск документов: максимум фото в обработке (под VRAM машины нейросети), таймаут, кэш повторов, сжатие фото; живой статус очереди/кэша/шлюза; проверка нейросети; тестовый прогон демо-скана с замером времени |
| «Настройки» | пороги уверенности (`confReupload/confReject/confAuto/minQuality`) и правила проверки полей |
| «Архитектура» | файловый проводник проекта (открыть/посмотреть/отредактировать файл) + карта системы с живыми статусами контуров |
| «База данных» | прямой просмотр таблиц Prisma |
| «Профили и доступы» | учётки, роли, должности, гранулярные права |

Права админа проверяются на сервере (`requireUser('admin')`) — интерфейс только отражает их.

## 7. Безопасность

- Фото и файлы загружаются и хранятся на серверах АЭМЗ; распознавание — собственная
  нейросеть на серверах АЭМЗ (сейчас показательно на отдельном GPU-ПК — временный
  стенд), облачных моделей нет (резерв GLM удалён, Task 79).
- OCR-шлюз и база слушают только 127.0.0.1; наружу — один внешний порт Caddy :81 (HTTP — стенд за песочницей).
- Сессия — подписанная HttpOnly-кука + Bearer-токен; пароли — scrypt-хеши.
- Сканы выдаются по токену с проверкой доступа (`/api/files/...`), без публичных ссылок.
- Файловый проводник и настройки нейросети — только админ; служебные папки
  (`node_modules`, `.next`, `.git`) скрыты, бинарные файлы не редактируются.
- Ключ 1С сравнивается за постоянное время; журналы не содержат содержимого запросов.
