# DEPLOY-LOCAL · Свой ПК как сервер стенда «АЗМЗ Логистика»

Этот документ — пошаговая инструкция для автономного развёртывания (может
исполнить человек или ИИ-агент на целевой машине). Цель:

> **ПК становится сервером** и для платформы «Контур 1С» (рабочее место
> диспетчера), и для приложения водителя. Телефон подключается по Wi-Fi и
> работает как клиент: браузер/PWA (рекомендуется) или нативный APK.

Общая схема и архитектура — в [README.md](./README.md).

## 0. Что получится в итоге

| Кто | URL | Что открывает |
|---|---|---|
| ПК (сам у себя) | `http://localhost:3000/` | приложение водителя |
| ПК (сам у себя) | `http://localhost:3000/kontur` | «Контур 1С» (диспетчер) |
| Телефон (та же Wi-Fi) | `http://<IP-ПК>:3000/` | приложение водителя |
| Телефон (та же Wi-Fi) | `http://<IP-ПК>:3000/kontur` | «Контур 1С» (диспетчер) |

Порт 3000 — роутер (`scripts/router.js`): он слушает все сетевые интерфейсы и
раскладывает `/kontur/*` на «Контур 1С» (:3001), остальное — на приложение
водителя (:3002). Наружу нужен только порт 3000.

## 1. Требования

- Windows 10/11, macOS или Linux;
- **Node.js 20+** (LTS, https://nodejs.org); проверка: `node -v`;
  менеджер `bun` не обязателен — везде ниже используется `npm`;
- **Git** (https://git-scm.com);
- ~2 ГБ свободного места (зависимости);
- телефон и ПК в **одной локальной сети** (один Wi-Fi-роутер).

## 2. Получить код

```bash
git clone https://github.com/vacantrix/drivemobile.git
cd drivemobile
```

В репозитории уже лежат базы SQLite с демо-данными (`db/custom.db`,
`kontur-1c/db/custom.db`) — ничего мигрировать и настраивать не нужно.

## 3. Установить зависимости

```bash
# корень — сервер приложения водителя
npm install

# «Контур 1С»
cd kontur-1c
npm install
cd ..
```

Адрес базы «Контура» задан в `kontur-1c/.env` (файл в репозитории):
`DATABASE_URL=file:../db/custom.db` — при запуске из папки `kontur-1c`
указывает на `kontur-1c/db/custom.db`. Менять ничего не нужно.

## 4. Запустить стенд

### Вариант А — Linux/macOS, одной командой

```bash
bash scripts/start-stack.sh
```

Скрипт поднимет :3001 («Контур 1С»), :3002 (приложение водителя) и :3000
(роутер), дождётся готовности и напечатает адреса.

### Вариант Б — Windows или вручную: три терминала

**Терминал 1 — «Контур 1С»:**

```bat
cd kontur-1c
npm run dev
```

(скрипт `dev` стартует Next.js на порту 3001)

**Терминал 2 — приложение водителя:**

```bat
cd <корень репозитория>
npx next dev -p 3002
```

**Важно:** не `npm run dev` в корне — тот стартует на порту 3000 и конфликтует
с роутером. Нужен именно порт 3002.

**Терминал 3 — роутер:**

```bat
node scripts/router.js
```

Оставьте все три терминала открытыми — это и есть работающий сервер.

## 5. Проверить на ПК (smoke-тест)

- `http://localhost:3000/` — открывается приложение водителя (тёмный экран
  «Главная» с кнопкой «Взять заявку»);
- `http://localhost:3000/kontur` — открывается «Контур 1С»;
- API живы (PowerShell: `curl.exe ...`, в cmd/macOS/Linux — `curl ...`):

```bash
curl http://localhost:3002/api/driver/v1/sync/pull?cursor=0   # JSON с "entries"
curl http://localhost:3001/kontur/api/1c/orders                # JSON со списком
curl http://localhost:3001/kontur/api/office/tracking          # JSON "rows"
```

## 6. Подключить телефон

1. **Узнать IP ПК:**
   - Windows: `ipconfig` → строка «IPv4-адрес», например `192.168.1.50`;
   - macOS: `ipconfig getifaddr en0`;
   - Linux: `ip addr show` (адрес Wi-Fi/WLAN-интерфейса).
2. **Брандмауэр Windows:** разрешить входящие TCP-соединения для Node.js на
   порт 3000. При первом старте `node` Windows обычно спрашивает сам —
   «Разрешить доступ». Либо вручную: Брандмауэр Защитника Windows →
   «Разрешить взаимодействие с приложением» → node.exe (галка «Частные сети»).
3. **На телефоне** (та же Wi-Fi сеть) открыть в браузере:
   - водитель: `http://192.168.1.50:3000/` (подставьте свой IP);
   - диспетчер: `http://192.168.1.50:3000/kontur`.
4. **Установить как приложение (PWA), рекомендуется:**
   - Android Chrome: меню `⋮` → «Установить приложение» (или «Добавить на
     главный экран»);
   - iOS Safari: «Поделиться» → «На экран “Домой”».
   Появится иконка, приложение откроется полноэкранным, маршруты и заявки
   будут кэшироваться офлайн (service worker).

Если телефон «не видит» ПК — см. раздел «Проблемы» (п. 10).

## 7. APK на телефон (по желанию)

**Для демо достаточно веб-версии (п. 6)** — она полнофункциональна: мгновенные
назначения (цикл 4–5 с), GPS-телеметрия для «Мониторинга (GPS)» диспетчера,
пометки, пробки, чат.

Нативный APK (`download/azmz-karkas`) — каркас прод-приложения. Его текущие
отличия от веб-версии: синхронизация по расписанию WorkManager (минимальный
интервал 15 минут; внеочередной цикл — при старте приложения и возврате сети),
GPS-телеметрия не реализована. Чтобы собрать APK, привязанный к вашему серверу:

1. Откройте `download/azmz-karkas/android/core/sync/src/main/kotlin/ru/azmz/logistics/driver/core/sync/AppGraph.kt`.
2. В строке `DEFAULT_BASE_URL` замените адрес на
   `http://<IP-ПК>:3000/api/driver/v1/` — **со слэшем на конце** (требование
   Retrofit). Роутер :3000 сам перенаправит запросы на сервер водителя.
3. HTTP без TLS для локальной сети уже разрешён манифестом
   (`android:usesCleartextTraffic="true"`).
4. Сборка:
   - **Android Studio** (проще): открыть папку `download/azmz-karkas/android`
     как проект → `Build → Build App Bundle(s)/APK(s) → Build APK(s)`;
     готовый файл — `app/build/outputs/apk/debug/app-debug.apk`;
   - **GitHub Actions** (без локального SDK): в karkas есть
     `.github/workflows/android-apk.yml`, но GitHub читает workflows только из
     **корня** репозитория — запушьте содержимое `download/azmz-karkas`
     отдельным репозиторием, Actions соберёт APK и выложит артефактом.
5. Установите APK на телефон (Android спросит разрешение на установку из
   «неизвестных источников»). Демо-водитель (Иванов С. П.) подставится
   автоматически.

## 8. Прод-режим (оптимизация, по желанию)

Дев-режим (п. 4) подходит для стенда и демо. Для постоянной работы быстрее
прод-сборка (команды ниже — без `bun`, на чистом `node`):

```bash
# приложение водителя (:3002)
npm run build                       # внутри используются cp -r; в PowerShell при
                                    # ошибке выполните вручную:
                                    #   Copy-Item -Recurse -Force .next/static .next/standalone/.next/
                                    #   Copy-Item -Recurse -Force public .next/standalone/
set PORT=3002                       # Linux/macOS: PORT=3002 node ...
node .next/standalone/server.js

# «Контур 1С» (:3001)
cd kontur-1c
npm run build
set PORT=3001
node .next/standalone/server.js
cd ..

# роутер как прежде
node scripts/router.js
```

Автозапуск при загрузке ОС (по желанию): Windows — Планировщик заданий на три
команды из п. 8 (или на `bash scripts/start-stack.sh` в Git Bash); Linux —
systemd-unit или cron `@reboot`.

## 9. Сквозной тест-чеклист (проверка, что всё работает)

1. **Диспетчер** (`/kontur` → «Заявки»): выбрать заявку → «Провести» (кнопка
   активна, когда вес груза не превышает грузоподъёмность ТС; подсказка о
   недостающих полях — жёлтый бейдж в «Диспетчерской»).
2. «Диспетчерская» → назначить водителя **Иванов С. П.** и ТС → создаётся рейс.
3. **Телефон водителя** (`http://<IP>:3000/`): на «Главной» в течение ~5–10 с
   появляется карточка «Вам назначена заявка ЗК-…» (пока тянется — спиннер
   «Синхронизация с 1С…»).
4. «Взять заявку» → фотофиксация → «Начать маршрут» → карта с маршрутом и
   движением.
5. **Диспетчер** → «Управление автопарком» → «Мониторинг (GPS)»: машина
   Иванова на карте, скорость и позиция обновляются каждые 5 с.
6. События рейса (погрузка, прибытие) появляются у диспетчера в карточке рейса
   («Рейсы»).
7. «Завершить рейс» у водителя → заявка уходит в «Историю», рейс закрывается
   у диспетчера.

## 10. Проблемы и решения

| Симптом | Причина и решение |
|---|---|
| Телефон не открывает `http://<IP>:3000` | ПК и телефон в разных сетях; в роутере включена «изоляция клиентов» (отключить); брандмауэр Windows режет порт 3000 (см. п. 6.2). Проверка с ПК: `http://<IP>:3000` в браузере самого ПК |
| У водителя красный чип «Офлайн» | Не поднят :3002 или телефон отвалился от Wi-Fi. Проверить `curl http://localhost:3002/` на ПК |
| Заявка не появляется у водителя | Не поднят «Контур 1С» (:3001) — именно он реплицирует назначения (мост-репликатор стартует вместе с ним). Проверить `curl http://localhost:3001/kontur/api/1c/orders`; счётчик реплики — `kontur-1c/db/bridge-state.json` (поле seq должно расти после назначений) |
| «Порт 3000/3001/3002 уже занят» | Windows: `netstat -ano | findstr :3000` → `taskkill /PID <pid> /F`; Linux: `ss -tlnp | grep 3000`. Либо поднять стенд на других портах (править `scripts/router.js` и команды запуска) |
| После перезагрузки роутера адрес ПК сменился | Назначить ПК статический IP в настройках роутера (DHCP reservation) |
| Вес заявки не проходит «Провести» | Вес груза больше грузоподъёмности всех ТС — уменьшить вес в заявке (кнопка активна при допустимом весе) |

## 11. Где что лежит на сервере

| Путь | Что это |
|---|---|
| `db/custom.db` | SQLite приложения водителя (заявки, журнал синхронизации, пометки, чат) |
| `kontur-1c/db/custom.db` | SQLite «Контура 1С» (справочники, заявки, рейсы, журнал регистрации) |
| `kontur-1c/db/bridge-state.json` | Водяная отметка моста «Контур → водитель» |
| `db/positions.json` | Последние GPS-позиции водителей (телеметрия) |
| `dev.log`, `kontur-1c/dev.log`, `router.log` | Логи сервисов |
| `scripts/start-stack.sh`, `scripts/kontur-restart.sh`, `scripts/reset-db.ts` | Управление стендом |

Сброс демо-данных к исходным: `git checkout -- db/custom.db kontur-1c/db/custom.db` (при остановленных серверах).
