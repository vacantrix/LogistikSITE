# ПРОМТ-ПЕРЕДАЧА: выгрузка результатов сессии «Контур 1С» в основную сессию

> Куда вставлять: **в сессию, которая разрабатывала платформу «Контур 1С»** (эмулятор 1С, Next.js, порт 3001).
> Когда: когда эта сессия сообщит, что платформа готова (или на любой паузе — чтобы зафиксировать состояние).
> Что делать с результатом: сессия выдаст блок `BEGIN HANDOFF … END HANDOFF`. Скопируй его целиком и вставь
> одним сообщением в основную сессию (та, что ведёт приложение водителя). Она сверит, объединит и продолжит работу:
> иконка, сборка приложения, установка на телефон.

## Текст промта (вставить ниже эту строку целиком)

Ты — сессия, которая построила веб-платформу **«Контур 1С»** (эмулятор 1С для приложения водителя «АЗМЗ Логистика»:
Next.js + TypeScript + Tailwind + shadcn/ui + Prisma, порт 3001; контракты `/api/1c/orders`, `/api/driver/v1/sync/*`,
`/api/office/*`). Сейчас твоя задача — **не писать новый код**, а собрать **HANDOFF-пакет**: полную, самодостаточную
выгрузку своего состояния, которую другая сессия (ведущая приложение водителя) прочитает без доступа к твоей машине,
файлам и истории переписки. Приёмник видит ТОЛЬКО то, что ты напечатаешь. Ничего важного не держи «в уме».

## Правила формата (обязательны)

1. Весь пакет — между маркерами `BEGIN HANDOFF` (первая строка ответа) и `END HANDOFF` (последняя).
2. Каждый файл — в отдельном fenced-блоке, первой строкой внутри блока — комментарий с точным путём от корня проекта:
   ```ts
   // src/app/api/1c/orders/route.ts
   <полное содержимое файла>
   ```
3. Не сокращай код молча: «…» и «остальное без изменений» запрещены. Либо файл целиком, либо он объявлен
   в списке пропущенных с причиной.
4. Если ответ не помещается в одно сообщение — режь на части: в конце каждой части строка `CONTINUED n/N`,
   следующая часть начинается с `HANDOFF PART n+1/N`. Заверши все части, не жди вопросов.
5. Не выдумывай: если что-то не реализовано или проверка не выполнялась — так и напиши в разделе «Проверено».

## Структура пакета (в этом порядке)

### Часть 1 — Манифест проекта
- Список реализованных фаз (по плану 0–5) и чего каждая достигла.
- Стек с версиями: Next.js, React, Prisma, провайдер БД (SQLite/Postgres), порт.
- Команды: установка, генерация Prisma-клиента, сид, dev-запуск, build. Все переменные окружения
  (`.env.example` целиком): `DATABASE_URL`, `GIS2_API_KEY`, `DRIVER_APP_ORIGIN`, `PORT` и все добавленные тобой.
- Дерево файлов проекта (полное, с пометками): `[NEW]` создан в этой сессии, `[EDIT]` изменён,
  `[SKIP]` не менялся. Для `node_modules`, `.next`, `uploads/` — не перечислять содержимое, только наличие папки.

### Часть 2 — Данные и ядро (файлы целиком)
- `prisma/schema.prisma` — целиком.
- Скрипт сида и фактические демо-данные после сида: перечисли реальные id/номера (справочники ТС и водителей,
  заявки с номерами вида ЗК-ГГГГ/NNNN, их статусы) — таблицей.
- Хелперы ядра: нумератор, журнал регистрации, статусная модель, правила проведения/назначения — файлами целиком.

### Часть 3 — API-контракты (файлы целиком + живые примеры)
- Все маршруты: `/api/1c/orders` (GET/POST), `/api/driver/v1/sync/pull|push|marks`, `/api/office/*`,
  все добавленные тобой. Файл целиком, путь над блоком.
- После каждого контракта — **реальный** пример запроса и ответа из твоего запуска (curl → JSON-ответ, 5–10 строк),
  а не сочинённый. Если контракт не проверялся curl'ом — пометь `NOT VERIFIED`.

### Часть 4 — UI (сжато)
- Список экранов/компонентов с путями; для каждого — одна строка: что делает.
- Целиком — только файлы, в которых живёт бизнес-логика (назначение, отмена, статусы на кнопках, маппинг).
- Чисто презентационные компоненты — только списком (тело не нужно).

### Часть 5 — Проверено / Не проверено / Пробелы
- «Проверено»: команды, которые ты реально выполнял, и их результат (сценарий приёмки 10.1 — какие шаги прошли,
  какие нет и на чём упались).
- «Не проверено»: что заявлено, но не гонялось.
- «Пробелы/TODO»: известные слабые места, заглушки, расхождения с исходным ТЗ, принятые допущения.
- «Интеграция»: точные инструкции для приложения водителя — на какой URL переключить `/api/1c/orders` и синхро-каналы
  (переменная `KONTUR_1C_URL`), какой заголовок идентификации водителя ожидает платформа, какие id водителей
  из сида годятся для `X-Driver-Id`, CORS/origin-ограничения, как запустить всё вместе для сквозного теста.

### Часть 6 — Если платформа может писать файлы
- Дополнительно сохрани в корень проекта `HANDOFF.md` с этим же пакетом и собери `kontur-1c-handoff.zip`
  (весь проект без `node_modules` и `.next`, плюс HANDOFF.md) — сообщи пути к обоим файлам. Если умеешь
  отдавать файлы пользователю — сразу приложи архив к ответу.

## Финал
Закончи пакет строкой `END HANDOFF`. После маркера — ничего. Не задавай встречных вопросов: если нечего
добавить — просто выгрузи пакет.
