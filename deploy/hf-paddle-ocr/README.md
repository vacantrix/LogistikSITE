# АЭМЗ PaddleOCR — OCR-движок платформы как Hugging Face Space

Тот же самый движок, что крутится на своём сервере (`mini-services/paddle-ocr`),
но в облаке HF: бесплатно **2 vCPU / 16 ГБ RAM**. Платформа (:3020) зовёт его как основной,
а локальный (:3031) остаётся автоматическим резервом — на время холодного старта Space.

## Зачем это нужно

| | Свой стенд | HF Space (free) |
|---|---|---|
| RAM | 4 ГБ (свободно ~1,8) | 16 ГБ |
| CPU | 2 vCPU | 2 vCPU |
| Режим | экономный (модель в subprocess на запрос, +5–20 с) | модель всегда в памяти |
| Мелкий шрифт | OCR_UPSCALE_BELOW=1100 | **1600** — увеличение чаще, точность выше |

## Как развернуть (10 минут)

1. **Соберите пакет**: `bash deploy/hf-paddle-ocr/pack.sh` — появится `hf-space-upload/` с 6 файлами
   (`Dockerfile`, `requirements.txt`, `README.md`, `engine.py`, `lexicon.py`, `server.py`).
2. **Создайте Space**: huggingface.co → New → Space → SDK **Docker** → **Blank**.
   Имя, например, `aemz-paddle-ocr`. Видимость: **Private** (или Public — API всё равно закрыт токеном).
3. **Загрузите файлы**: Files → Add file → Upload files → перетащите 6 файлов из `hf-space-upload/`.
   Сборка займёт 5–15 минут (paddlepaddle весит ~600 МБ, модели качаются при сборке).
4. **Токен**: Settings → Variables and secrets → New **secret** `OCR_TOKEN` (произвольная длинная строка).
   Это общий секрет: движок отвечает только запросам с заголовком `X-OCR-Token: <значение>`.
5. **Подключите платформу** (на своём сервере, переменные окружения шлюза :3020):
   ```bash
   PADDLE_OCR_URL=https://<ваш-логин>-aemz-paddle-ocr.hf.space/ocr
   PADDLE_OCR_TOKEN=<то же значение OCR_TOKEN>
   # опционально, только для Private Space:
   PADDLE_OCR_HF_TOKEN=hf_...            # Access token с правом вызова Space
   # опционально: другой локальный резерв (по умолчанию http://127.0.0.1:3031/ocr)
   # PADDLE_FALLBACK_URL=http://127.0.0.1:3031/ocr
   ```
   и перезапустите шлюз :3020. URL Space виден справа сверху (⋮ → Embed this Space) — это
   `https://<ваш-логин>-<имя-space>.hf.space`.

Проверка: `curl https://<ваш-логин>-aemz-paddle-ocr.hf.space/health` → `{"ok": true, "ready": true, ...}`.
Локальный стенд можно не трогать — он станет резервом автоматически.

## Что важно знать (бесплатный тариф)

- **Сон**: Space засыпает после ~48 ч без HTTP-запросов; холодный старт 2–5 минут.
  Платформа это переживёт: шлюз дождётся или уйдёт на локальный движок (`chain: paddleocr:fail→local`).
  Чтобы не спал — дёргайте `/health` раз в сутки (можно внешним пингером, например cron-job.org, UptimeRobot).
- **Пересборка**: правка любого файла в Space перезапускает контейнер — те же 2–5 минут простоя,
  фолбэк на локальный закрывает этот простой.
- **Квоты CPU**: 2 vCPU — как на своём стенде. Скорость одного документа сопоставимая (5–40 с),
  выигрыш — в RAM: точное чтение бледных/мелких строк без OOM.
- **Персональные данные**: фото документов будут уходить с вашего сервера на инфраструктуру HF
  (HTTPS + токен). Если это недопустимо по вашим требованиям — не подключайте Space, локальный
  движок остаётся единственным (по умолчанию так и есть).

## Контракт API (тот же, что у локального :3031)

- `GET /health` → `{"ok": true, "ready": true, ...}` (без токена; он лишь должен быть валиден, если задан)
- `POST /ocr` — заголовок `X-OCR-Token` обязателен, когда в Space задан secret `OCR_TOKEN`;
  тело `{ image, docType, fields[] }` (формат шлюза) или `{ type, dataUri, intake? }` (формат платформы);
  ответ `{ quality, fields, confidences, docType, side?, confirmations? }`
